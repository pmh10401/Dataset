교차 운영체제 서비스 설계

Windows와 Mac에서 함께 쓰는 시계열 이상 진단 서비스

한 대의 중앙 서버에서 프로그램을 실행하고, 연구팀은 Windows나 Mac의 브라우저로 접속합니다. 원본 데이터는 네트워크로 업로드하지 않고 서버에서 직접 등록합니다.

실행 프로그램

Windows와 Mac에서 각각 만든 실행 아이콘이 서버를 시작하고 준비가 끝나면 브라우저를 엽니다. 운영체제 부팅 시 자동 실행은 하지 않습니다.

웹 작업 공간

새 분석, 작업 대기열, 분석 기록, 분석 결과를 제공합니다. 연구팀 PC에는 별도 분석 프로그램을 설치하지 않습니다.

응용 서버

현재 Python HTTP 서버와 API를 재사용합니다. 여러 브라우저 요청은 받을 수 있지만 실제 분석은 한 건씩 처리합니다.

분석 엔진

현재 검증된 점수, 라우팅, p값, 다중 증거 규칙을 그대로 사용합니다. 운영체제가 달라져도 판정 기준은 바꾸지 않습니다.

원본 데이터 DB

서비스는 읽기 전용으로 엽니다. 시계열 값은 현재 방식처럼 float32 이진 배열로 저장해 샘플마다 행을 만드는 낭비를 피합니다.

분석 결과 DB

대기·실행·완료·실패 상태와 결과를 별도 SQLite DB에 저장합니다. 서버를 다시 실행해도 분석 기록이 남습니다.

단순화 결정: 10명 이내에서는 현재의 ThreadingHTTPServer, 분석 작업자 1개, SQLite 두 개를 유지합니다. Redis, 별도 작업 서버, PostgreSQL, Electron은 지금 추가하지 않습니다.

3. 실행 흐름

  1. 관리자가 Windows 또는 Mac 중앙 서버에서 실행 아이콘을 누릅니다.
  2. 프로그램은 DB와 모델 자료를 검사하고 내부 웹 서버를 시작합니다.
  3. 준비가 끝난 뒤 중앙 서버의 기본 브라우저를 자동으로 엽니다.
  4. 다른 연구원은 내부 네트워크 주소로 같은 화면에 접속합니다.
  5. 사용자가 DB에 등록된 데이터셋 이름을 검색하고 하나를 선택합니다.
  6. 사용자가 분석 시작을 누르면 요청이 공용 대기열에 저장됩니다.
  7. 분석 작업자는 원본 DB를 읽고, 사용 가능한 검증된 계산 경로로 결과를 만듭니다.
  8. 완료 결과를 별도 DB에 저장하고 웹 화면에 이상 시계열과 검토 후보를 표시합니다.

4. 네트워크 업로드 없는 데이터 등록

웹 서비스에는 파일 업로드 화면과 업로드 API를 두지 않습니다. 데이터 등록은 중앙 서버에서만 실행하는 로컬 등록 프로그램이 담당합니다.

  1. 서비스를 종료합니다.
  2. 관리자가 승인된 원본 파일이나 DB를 서버의 incoming 폴더에 직접 복사합니다.
  3. 로컬 등록 프로그램이 데이터셋 이름, TRAIN·TEST 구분, 시계열 길이, 결측값, 무한값, 라벨 수를 검사합니다.
  4. 원본 TRAIN에서 가장 많이 등장하는 라벨을 정상 클래스로 정하고, 원래 라벨과 변환 규칙을 등록 기록에 남깁니다.
  5. 서비스가 사용하는 파생 DB에서는 정상 TRAIN을 표준 라벨 0으로 저장합니다. 서비스는 이 완성된 파생 DB를 읽으므로 숫자 0을 임의로 정상이라고 가정하지 않습니다.
  6. 새 DB를 별도 파일로 끝까지 만든 뒤 검사가 통과한 경우에만 현재 DB와 교체합니다.
  7. 서비스를 다시 실행하면 새 데이터셋 목록을 읽습니다.

등록 성공과 분석 가능은 구분합니다. 현재 검증 자료에 적용 경로가 없는 새 데이터셋은 목록에는 표시하되 검증된 분석 경로 없음으로 표시합니다. 교차 운영체제 변환 과정에서 이름만 보고 임의의 방법을 배정하지 않습니다.

첫 버전의 의도적인 제한: DB 등록 중에는 서비스를 중지합니다. 무중단 교체가 실제로 필요해질 때만 버전 포인터와 자동 새로고침을 추가합니다.

5. Windows·Mac 패키지

항목설계 결정
빌드Windows 패키지는 Windows에서, Mac 패키지는 Mac에서 각각 만듭니다. 다른 운영체제용 실행 파일을 교차 생성하지 않습니다.
설치 경험Python을 따로 설치하지 않는 자체 포함 패키지를 제공합니다. 압축 해제 또는 설치 후 실행 아이콘을 누르는 방식입니다.
파일 위치Mac은 .app 옆, Windows는 .exe 옆의 data를 사용합니다. 모델 자료와 화면은 패키지 내부에 포함됩니다. 데이터 위치는 --data-dir로 변경합니다.
로컬 등록같은 실행 파일에 --import-database를 지정하면 기존 DB 등록기를 실행한 뒤 종료합니다. 별도 Python이나 HTTP 업로드 없이 등록할 수 있습니다.
모델 자료서비스가 실험 폴더를 직접 찾지 않도록 검증된 라우팅·전처리 자료와 해시를 서비스의 resources 폴더에 묶습니다.
팀 접속실행 아이콘은 내부 네트워크에서 사용할 서버 주소와 포트로 시작합니다. 준비가 끝나면 연구팀에 보여줄 접속 주소를 화면에 표시합니다.
실행 환경두 패키지는 같은 Python·Numba·분석 라이브러리 버전과 모델 자료 해시를 기록한 manifest를 포함합니다.
업데이트프로그램 파일과 data 폴더를 분리해 프로그램을 교체해도 원본 DB와 결과 DB가 지워지지 않게 합니다.
종료실행 창이나 종료 메뉴에서 대기 중 작업을 정리한 뒤 서버를 닫습니다. 강제 종료된 작업은 다음 실행에서 중단 상태로 표시합니다.

6. CPU와 선택적 가속

CPU·Numba를 필수 기준 구현으로 둡니다. CUDA나 Apple Silicon 가속 장치가 있다는 이유만으로 자동 사용하지 않습니다.

  1. 프로그램 시작 시 운영체제와 사용 가능한 장치를 확인합니다.
  2. 해당 분석 단계에 이미 검증된 CUDA 또는 MLX 구현이 있을 때만 후보로 둡니다.
  3. 같은 입력과 시드에서 CPU와 후보 가속 경로의 후보 인덱스가 같고, 수치 차이가 허용 범위 안인지 확인합니다.
  4. 전체 단계가 CPU보다 최소 1.1배 빠를 때만 가속 경로를 사용합니다.
  5. 가속 경로가 시작되지 않거나 실행 중 실패하면 그 작업을 CPU로 한 번 다시 실행하고 결과에 실제 사용 장치를 기록합니다.

현재 공식 변환기가 CPU 전용이면 그대로 둡니다. GPU 사용을 위해 검증된 알고리즘을 다시 쓰지 않습니다.

7. 사용성 중심 UI

승인된 HTML UI 시안 열기

한 화면, 한 목적

새 분석 화면은 데이터셋 검색, 선택 내용 확인, 분석 시작만 강조합니다. 부가 지표는 결과 화면으로 보냅니다.

빠른 검색

현재 DB가 보고하는 전체 데이터셋을 이름으로 바로 좁힙니다. 개수는 DB 등록 결과에 따라 자동으로 갱신합니다.

분명한 선택 상태

선택한 데이터셋의 학습·평가 수, 길이, 정상 기준, 분석 경로를 분석 전에 보여줍니다.

절제된 화면

시스템 글꼴, 넓은 여백, 얇은 구분선, 하나의 파란 강조색을 사용합니다. 장식용 카드·그라데이션·배지를 반복하지 않습니다.

상태를 말로 표시

색만으로 정상·경고·실패를 구분하지 않습니다. 대기 순서와 실패 이유를 쉬운 문장으로 함께 표시합니다.

결과 우선순위

결과 화면은 자동 확정 이상, 표본 수 제한 경고, 다중 증거 검토 후보, 세부 성능 지표 순으로 보여줍니다.

9. 오류 처리

  • 원본 DB나 검증 모델 자료가 없으면 분석 서버를 열지 않고, 누락된 파일 이름과 해결 방법을 표시합니다.
  • DB 등록 검사에 실패하면 기존 DB를 그대로 유지하고, 실패한 데이터셋과 이유를 HTML 보고서로 남깁니다.
  • 분석 실패는 결과 DB에 저장하고 대기열 화면에서 이유와 다시 실행 버튼을 보여줍니다.
  • 서버를 강제 종료했을 때 실행 중이던 작업은 다음 실행에서 중단됨으로 바꿉니다.
  • CUDA 또는 MLX 오류는 CPU 재실행으로 복구하되, 두 경로가 모두 실패하면 원인을 숨기지 않고 작업 실패로 저장합니다.

11. 완료 검증

  • 실제 Windows와 실제 Mac에서 아이콘 실행 후 브라우저 화면이 열립니다.
  • Python이 설치되지 않은 시험 PC에서도 자체 포함 패키지가 시작됩니다.
  • Windows와 Mac의 CPU 경로가 같은 기준 데이터에서 같은 자동 이상 및 검토 후보 인덱스를 만듭니다.
  • 로컬 등록 프로그램이 정상 클래스 원본 라벨을 최다 빈도로 결정하고 파생 DB에 정확히 기록합니다.
  • 등록 실패 시 기존 DB가 바뀌지 않습니다.
  • 검증된 분석 경로가 없는 새 데이터셋은 등록되지만 실행할 수 없는 이유가 분명하게 표시됩니다.
  • 10명의 브라우저가 동시에 목록과 기록을 조회하고 분석 요청을 넣을 수 있습니다.
  • 분석은 한 건씩 실행되며 대기 순서와 실패 상태가 모든 사용자에게 동일하게 보입니다.
  • 웹 화면과 API 어디에도 데이터 업로드 기능이 존재하지 않습니다.
  • 선택적 GPU 경로는 CPU 판정 일치와 1.1배 속도 기준을 통과한 단계에서만 활성화됩니다.
  • 서버를 다시 실행해도 완료 기록이 유지되고 중단 작업이 올바르게 표시됩니다.
  • 키보드 검색, 선택, 분석 시작, 대기열, 기록, 결과 확인을 엔드투엔드로 검증합니다.

12. 나중에 확장하는 기준

지금은 사용하지 않음추가할 실제 조건

Redis 또는 별도 작업 서버단일 분석 작업자로 대기 시간이 허용 범위를 넘을 때
무중단 DB 교체데이터 등록 시간에도 서비스를 계속 제공해야 할 때

13. 최종 결정 요약

한 개의 Python 중앙 서비스와 한 개의 웹 UI를 유지하고, Windows와 Mac용 자체 포함 실행 패키지만 각각 만듭니다. 원본 데이터는 서버에서 로컬 등록하고, 분석 요청에는 데이터셋 식별자만 사용합니다. CPU·Numba는 항상 동작하며 GPU는 검증된 경우에만 선택적으로 사용합니다.
