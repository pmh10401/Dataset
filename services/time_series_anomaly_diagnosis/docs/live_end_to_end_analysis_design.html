실시간 엔드 투 엔드 이상 진단 설계

현재 대상의 데이터셋 이름별 표와 저장된 TEST 행 번호를 사용하지 않고, 현재 DB 값만으로 분석 방법·점수·검토 후보를 계산하기 위한 설계입니다.

설계 승인 구현 계획 사용자 승인 작성일 2026-09-06

1. 목표와 완료 기준

완료 기준: 새 데이터셋을 DB에 추가해도 그 데이터셋의 이전 결과나 이름별 규칙 없이 현재 입력만으로 같은 분석 흐름이 실행되어야 합니다. C가 통과할 때만 이름 없는 공통 학습 산출물을 사용할 수 있습니다.
  • 데이터셋 이름은 DB 조회와 화면 표시에만 사용합니다.
  • 서비스는 이미 파생 DB에서 label=0으로 저장된 정상 TRAIN만 사용하며, 실행 중 정상 클래스를 다시 추정하지 않습니다.
  • 현재 분석 대상과 바깥쪽 최종 검증 family의 TEST 라벨은 후보가 모두 결정된 뒤 성능 평가에만 사용합니다.
  • 검토 후보는 자동 이상으로 승격하지 않습니다.

2. 현재 구조에서 제거할 의존성

현재 기능문제목표

강한 검토 후보현재 후보와 저장된 Hard 행 번호를 비교현재 실행의 반복 결과만 사용
P1·P2·P3저장된 TEST 행 번호를 조회현재 방법·초기값의 실제 지지 수로 계산

기존 실험 자료는 연구 재현 자료로 남기지만 서비스 실행 경로에서는 읽지 않습니다.

3. 새 데이터 흐름과 전처리 규칙

SQLite 데이터베이스
  → 현재 TRAIN 정상값·TEST 값 읽기
  → 모든 데이터셋에 같은 값 기반 전처리 적용
  → MiniRocket·Hydra·MultiRocket 후보 계산
  → TRAIN 기준 점수와 TEST 점수를 비교해 p값 계산
  → 자동 이상 / 현재 다중 증거 검토 후보 확정
  → 예측 결과 고정
  → TEST 라벨 읽기 및 성능 평가
  → 분석 기록 저장 및 웹 화면 표시

표준/복구 목록을 따로 두지 않습니다. 원자료의 정상 클래스 결정과 이진 라벨 변환은 이 서비스보다 앞선 파생 DB 생성 단계의 고정 계약입니다. 서비스는 label=0인 TRAIN 값과 라벨을 조회하지 않은 TEST 값만 읽고 다음 규칙을 똑같이 적용합니다.

  1. 잘못된 바이너리 값은 해당 데이터셋의 분석을 중단하고 이유를 표시합니다. NaN·Inf가 있는 행은 제외합니다.
  2. 남은 정상 TRAIN 행이 5개 미만이거나 TEST 행이 없으면 분석 불가로 표시합니다.
  3. 목표 길이는 남은 정상 TRAIN 길이의 작은 쪽 중앙값으로 정합니다.
  4. 모든 행을 그 길이로 선형 재표본화합니다. 이미 같은 길이면 값을 그대로 복사합니다.
  5. 각 행을 평균 0, 표준편차 1로 맞춥니다. 상수 행은 분석 불가로 표시합니다.

이는 검증된 기존 Numba 복구 전처리를 모든 데이터셋에 재사용하는 최소 변경안입니다. 데이터셋 이름을 바꾸더라도 값이 같으면 분석 방법과 결과가 같아야 합니다.

4. 비교할 세 가지 방법

방법장점한계
A. 단일 MiniRocket가장 단순하고 현재 1,117개 중 1,028개에서 선택됨Hydra가 유리했던 데이터의 성능 저하 가능성
B. 세 방법 합의이름 없이 현재 다중 증거를 직접 계산실행 시간이 늘고 합의 규칙 검증이 필요
C. TRAIN 특징 라우터최종 실행은 한 방법만 사용해 효율적가족 분리 학습·검증이 필요하고 과적합 위험이 있음

권장: B를 이름 없는 기준안으로 먼저 만들고 A·C와 같은 조건에서 비교합니다. 결과를 보기 전에 규칙을 고정하고, 성능 기준을 통과한 승자만 서비스에 넣습니다.

5. p값과 후보 판정 계약

점수 방법은 기존 minirocket_local_gap, multirocket_local_gap, hydra_local_gap만 사용합니다. 커널 수는 각각 4,096개, 1,024개, 8개이며 가까운 이웃 3개, TRAIN 기준 최대 1,000개, 처리 묶음 128개로 고정합니다.

5겹 교차검증은 초기값으로 TRAIN 행 순서를 섞고 다섯 묶음으로 가능한 한 고르게 나눈 뒤, 네 묶음으로 학습하고 남은 한 묶음의 기준 점수를 만드는 현재 방식을 그대로 사용합니다. 1,000개를 넘는 기준 행의 선택법과 세 변환기의 세부 설정은 현재 점수 코드·설정 파일을 그대로 재사용하며, 두 파일의 SHA-256과 패키지 버전을 실행 계약에 고정합니다.

각 방법은 고정된 두 초기값 20260721, 20261721로 실행합니다. 기존 한 초기값 복구 경로도 두 초기값으로 바꿉니다. 각 실행은 TEST 라벨을 보지 않고 TRAIN 교차검증 점수와 TEST 점수를 비교합니다.

p = (1 + TEST 점수 이상인 TRAIN 점수 수) / (TRAIN 수 + 1)입니다. 두 초기값의 TRAIN 점수와 TEST 점수는 각각 중앙값으로 합친 뒤 방법별 최종 p값을 다시 계산합니다.

구분정확한 규칙
방법 지지해당 방법의 최종 p값이 0.005 이하
최소 p 지지1 / (TRAIN 수 + 1) > 0.005이고, 해당 시계열의 p값이 이 가능한 최소값과 1e-15 이내로 같음
A·C 자동 이상선택된 한 방법이 방법 지지
B 자동 이상세 방법 중 둘 이상이 방법 지지
반복 검토 후보자동 이상이 아니며, 한 방법의 두 초기값이 모두 같은 시계열을 최소 p로 지지
B 다중 방법 검토 후보자동 이상이 아니며, 세 방법 중 둘 이상이 같은 시계열을 최소 p로 지지

A와 C의 반복 검토 후보는 선택된 방법에서만 seed_consensus를 계산합니다. B는 세 방법 각각의 seed_consensus와 세 방법 사이의 method_consensus를 합칩니다. 모든 검토 후보는 자동 이상과 중복시키지 않습니다.

서로 다른 방법의 원점수는 평균내지 않습니다. A·C와 현재 비교 기준의 정렬 및 ROC AUC 점수는 선택된 방법의 최종 p값에 대한 1 - p입니다. B는 세 방법 p값 중 두 번째로 작은 값의 1 - p를 사용합니다. 동률이면 원래 TEST 행 번호가 작은 순서로 표시합니다. 화면에는 시계열 번호, 최종 p값, 초기값별 p값, 지지 방법만 표시합니다.

평가 전에 이 규칙, 패키지 버전, 입력 데이터 목록과 해시를 실행 계약에 기록합니다. 새 증거 이름은 seed_consensus와 method_consensus로 하며 P1·P2·P3 이름을 재사용하지 않습니다.

Trace_normal_2 #49는 MiniRocket의 두 초기값에서 모두 점수 1위·최소 p값이므로 저장된 Hard 목록 없이 반복 검토 후보가 됩니다.

6. TRAIN 특징 라우터의 학습 경계

C는 이미 검증한 다음 일곱 가지 TRAIN 특징만 사용합니다: 시계열 길이, 정상 TRAIN 수, 주파수 복잡도, 치우침, 뾰족함, 변화량 비율, 0 교차 비율. 데이터셋 이름, family 이름, TEST 값·라벨·점수는 입력하지 않습니다. 특징 공식을 새로 만들지 않고 기존 검증 함수와 그 SHA-256을 그대로 고정합니다. 시계열 길이와 TRAIN 수에는 log(1+x)를 적용하고, 유한하지 않은 값은 학습군 중앙값으로 바꾼 뒤 학습군 평균과 표준편차로 크기를 맞춥니다. 표준편차가 0인 축은 1로 두고 유클리드 거리를 사용합니다.

  • 원자료 family 하나를 통째로 최종 검증군으로 빼고, 나머지 family만 학습에 사용합니다.
  • 안쪽 학습 family의 TEST 라벨은 세 방법의 학습용 성능표를 만드는 데만 사용할 수 있습니다. 현재 분석 대상과 바깥쪽 최종 검증 family의 라벨은 라우팅 뒤에만 읽습니다.
  • 학습 행은 데이터셋 하나당 한 행이며 family는 익명 묶음 번호로만 보관합니다. 거리가 같으면 고정된 입력 순서를 유지하고, 각 묶음에서 가장 가까운 한 행만 남긴 뒤 가까운 31개를 사용합니다.
  • MultiRocket과 Hydra는 각각 이 31개에서 평가합니다. 20개 이상이 있어야 하며, MiniRocket 대비 AUC 차이와 ZF 개수 차이가 0 이상인 비율이 각각 90% 이상이어야 합니다. AUC 차이의 하위 20%가 0 이상이고 평균 ZF 개수 차이가 0보다 클 때만 MiniRocket 대신 선택합니다.
  • 둘 다 통과하면 평균 ZF 차이, AUC 차이의 하위 20%, 고정 순서 MultiRocket·Hydra 순으로 비교합니다. 숫자는 별도 허용 오차 없이 그대로 비교하고 둘 다 탈락하면 MiniRocket으로 돌아갑니다.
  • 서비스에는 특징 기준, 거리 정규화 값, 방법별 성능 차이만 담은 학습 산출물을 넣을 수 있습니다. 데이터셋 이름과 TEST 행 번호는 넣지 않습니다.

이 공통 학습 산출물은 C가 성능 기준을 통과한 뒤 전체 검증 자료로 한 번 다시 학습해 만듭니다. 현재 분석 대상의 이름으로 이전 결과를 찾는 표와는 다릅니다.

7. 성능 평가와 선택 규칙

현재 성능 기준: 모든 정책과 같은 공통 전처리·두 초기값 점수 캐시를 사용하되, 방법 선택만 현재 검증된 1,117개 라우팅 결정을 그대로 적용합니다. 선택 방법의 최종 p값이 0.005 이하면 자동 이상이며, 표본 수 때문에 기준에 도달할 수 없고 최종 p값이 가능한 최소값이면 기존 소표본 검토 후보입니다. 동결 Hard·P1·P2·P3와 seed 일치 조건은 넣지 않습니다. 이 이름 기반 결정은 비교 평가기에만 존재하고 라이브 서비스와 통과 정책 산출물에는 포함하지 않습니다.

공식 1,117개 모집단은 현재 검증된 라우팅 결과 파일(SHA-256 7038b994e422dc93a18927c810ce5e3bdb7601039ba01d2b388895444e09956f)의 evaluation.decisions[].dataset을 정렬해 얻은 중복 없는 이름으로 고정합니다. 현재 DB에 추가된 CornellWhaleChallenge와 Phoneme_normal_39는 이 회고 비교에서만 제외하며, 라이브 카탈로그는 이름표 없이 값 조건을 통과하면 새 데이터셋도 분석합니다.

먼저 이 공식 1,117개 모두에 값 기반 전처리를 시도하고, 라벨을 읽기 전에 분석 가능한 공통 목록을 고정합니다. 목록과 예측 행 수의 SHA-256을 저장한 뒤 별도의 평가 연결에서 TEST 라벨을 읽습니다. 전처리 불가 데이터는 전체 범위와 이유에 남기되 성능 분모에는 넣지 않습니다. 현재 기준·A·B·C 중 하나라도 이 공통 목록에서 실패하거나 행을 빠뜨리거나 중복시키면 해당 방법은 탈락하며 분모는 줄이지 않습니다.

지표계산
잔여 FN 합계자동 이상과 검토 후보 어디에도 포함되지 않은 실제 이상 수의 합
잔여 FN 비율잔여 FN / 전체 실제 이상 수
검토 포함 FP 합계자동 이상 또는 검토 후보에 포함된 실제 정상 수의 합
자동 FP 합계자동 이상에 포함된 실제 정상 수의 합
family 균형 평균먼저 데이터셋별 비율을 구해 family 안에서 평균하고, 다시 모든 family를 같은 비중으로 평균

현재 성능 기준도 같은 공통 목록에서 다시 계산하고 예측 파일의 SHA-256을 기록합니다. A·B·C가 서비스 후보가 되려면 잔여 FN 합계와 family 균형 잔여 FN 비율이 모두 현재 기준보다 낮고, 두 FP 합계는 현재 기준보다 늘지 않아야 합니다.

여러 방법이 통과하면 잔여 FN 합계, family 균형 잔여 FN 비율, 검토 포함 FP 합계, 자동 FP 합계, 고정 순서 A·B·C 순으로 고릅니다. 데이터셋별 ROC AUC의 단순 평균과 family별 평균을 다시 같은 비중으로 평균한 AUC, 처리 시간은 보조 지표로만 기록합니다. 검토 후보를 자동 탐지 성능으로 보고하지 않습니다.

8. 구현 단계

  1. 격리된 작업 폴더에서 공통 전처리와 세 점수 방법을 서비스 내부 코드로 만듭니다. 현재 8485 서비스는 아직 바꾸지 않습니다.
  2. 모든 방법에서 같은 두 초기값 결과로 반복 검토 후보를 계산합니다.
  3. A·B·C 비교 실행기를 만들고 작은 smoke 데이터로 결정 일치성을 확인합니다.
  4. Numba와 MLX는 동일 결정·수치 허용 범위·전체 단계 1.1배 속도 조건을 통과할 때만 사용합니다.
  5. 가족 분리 조건으로 공식 1,117개 전체의 준비 상태를 확인하고, 고정된 공통 분석 가능 목록을 평가합니다.
  6. 통과한 승자만 서비스에 통합하며, 그때 동결 Hard·P1·P2·P3와 이름별 라우팅·복구 목록의 라이브 연결을 제거합니다. 통과한 방법이 없으면 현재 서비스를 유지하고 다음 실험으로 넘깁니다.

9. 검증 항목

  • 같은 값과 다른 데이터셋 이름에서 결과가 동일합니다.
