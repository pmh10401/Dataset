동작

  • 공개 명령은 bare inspect와 evaluate --reviewed-commit LOWER40HEX만 받는다.
  • private capability seam은 non-official Path 하나만 받고, 새 결과 경로만 출판한다.
  • evaluate는 고정 TRAIN 경로, 96→140 보간, 2 seeds×5 folds, Task 3 scorer, Task 4 판정·출판·재생을 한 번 연결한다.
  • inspect는 기존 private root의 semantic replay만 열며, CLI의 TRAIN loader와 fold scorer를 다시 호출하지 않는다.
  • 공식 root 생성, TEST 접근, label query는 하지 않는다.
  • launcher의 내부 capability는 run1 또는 run2만 각각 사전등록 private root로 해석한다. CLI 인자로 root를 받을 수 없다.
  • inspect는 저장된 seven leaves의 hash, 원점수 AUC, confirmation, Wilson 설명값, pair 진단, 요약, 결정과 대시보드를 다시 계산한다. Exp464·Task 3 scorer를 호출하지 않는다.

RED → GREEN

RED: CLI와 launcher가 없는 상태에서 새 7개 CLI 테스트를 실행했다. 예상대로 모듈 import와 launcher 경로가 없어 5 errors, 2 failures가 발생했다.

GREEN: 최소 CLI·launcher를 구현한 뒤, create-only root, clean commit, duplicate process, lazy import, outside-CWD runtime, 10-fold Task 2→4 private fixture 흐름을 통과시켰다.

보정 RED: fresh review가 launcher capability 부재와 inspect의 Exp464 scorer 재호출을 지적했다. authorized run1 launcher와 Exp464/Task 3 scorer를 모두 차단한 inspect 테스트가 기존 코드에서 실패하는 것을 확인했다.

보정 GREEN: launcher는 두 사전등록 private root만 주입하도록 했고, inspect는 persisted evidence-only 재생으로 바꿨다. scorer를 모두 차단한 상태에서도 evaluate와 inspect 출력이 같다.
