Exp471 Task 2 — Numba ACF peak-lag 단일 scorer

  • contracts_antigravity.py는 Task 2와 이후 qualification이 호출하고, immutable 결과 경계를 정하며 test_contracts_antigravity.py가 검사한다.
  • Task 2는 새 모듈만 추가한다. 기존 Task 1 authority 모듈의 의미나 direct object identity를 바꾸지 않는다.

고정 수식

  • 입력은 유한한 float64 2차원 배열이며 열 수는 정확히 140이다. fit 행은 LOO를 위해 최소 2개다.
  • early 창은 [0:56], late 창은 [84:140]다.
  • 각 창은 median으로 중심화하고 1.4826 × MAD로 나눈다. scale이 유한한 양수가 아니면 즉시 ValueError다.
  • biased ACF 분모는 56개 z 제곱합, 분자는 lag만큼 겹치는 곱의 합이다. lag 1..25를 계산한다.
  • peak 후보는 lag 2..24에서 양수이고 왼쪽보다 크며 오른쪽보다 크거나 같은 값이다. 가장 큰 값을 고르고 동점은 가장 작은 lag다. 후보 없음은 integer 0과 presence=false다.
  • row shift는 late_peak - early_peak다. peak와 presence를 모두 보존한다.
  • fit raw는 각 fit shift와 나머지 fit shifts의 median 사이 절댓값이다. query raw는 query shift와 전체 fit shifts median 사이 절댓값이다.
  • query rank는 (1 + count(fit_raw <= query_raw)) / (n_fit + 1)다.
  • strict confirmation은 query_raw > 0이고 query_raw > max(fit_raw)다.

생산 파일과 API

  • experiments/exp471_ecg200_acf_peak_lag_shift_numba_antigravity/acf_peak_lag_antigravity.py
  • experiments/exp471_ecg200_acf_peak_lag_shift_numba_antigravity/python_reference_antigravity.py
  • tests/test_acf_peak_lag_antigravity.py, tests/test_python_reference_antigravity.py

acf_peak_lag_antigravity.py는 ACFPeakLagScoresAntigravity, dominant_peak_from_acf_numba_antigravity, peak_shift_row_numba_antigravity, assemble_raw_rank_numba_antigravity, score_acf_peak_lag_numba_antigravity를 제공한다. 모든 Numba kernel은 @numba.njit(cache=False, fastmath=False)다. production NumPy scorer나 자동 fallback은 만들지 않는다.

결과 dataclass는 fit/query early·late peak lag, 2열 presence, integer shift, raw, query rank, confirmation, fit maximum, backend를 보존한다. 배열은 입력에서 복사하고 C-contiguous로 고정하며 writeable=false로 만들어 외부 mutation을 막는다.

python_reference_antigravity.py는 list, math.fsum, sorted를 계산 authority로 사용한다. NumPy 벡터 연산으로 별도 production scorer를 만들지 않는다. 반환 형태와 배열 dtype/shape/order는 Numba 결과와 같고 backend만 python_reference다.

TDD와 필수 테스트

  1. production 파일보다 먼저 두 테스트 파일을 만들고 import failure RED를 기록한다.
  2. period 8→10 fixture가 peak (8,10), presence (true,true), shift 2인지 검사한다.
  3. peak 최대값 동점은 작은 lag, 후보 없음은 (0,false)인지 검사한다.
  4. 양의 scale과 offset을 적용해도 peak/shift가 같은지 검사한다.
  5. constant 또는 MAD 0 창, NaN/Inf, 잘못된 차원·폭·dtype, fit 1행을 거부하는지 검사한다.
  6. Python과 Numba의 peaks, presence, shifts, ranks, confirmations가 같고 raw/max 오차가 1e-12 이하인지 검사한다.
  7. 결과 배열이 올바른 dtype/shape이고 수정 불가능한지 검사한다.
  8. Numba 함수가 실제 dispatcher이며 nopython_signatures가 생기는지 검사한다.
