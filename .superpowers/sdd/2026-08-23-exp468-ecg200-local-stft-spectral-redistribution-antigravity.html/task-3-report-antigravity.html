Exp468 Task 3 — BLOCKED_AT_ACCELERATION_GATE

후속 상태: 이 문서는 승인 전 시점의 BLOCKED 상태를 보존하는 point-in-time 기록이며, 현재 authoritative closure는 task-3-fallback-report-antigravity.html이다.

결론: 고정 S10 수식과 Numba parity는 통과했지만 clean-process backend 준비와 cold compile을 포함한 1.1x 가속 gate가 실패했다. MLX도 float64 RFFT를 유지하지 못한다. NumPy CPU fallback을 기록하고 Task 3·Step 5를 미체크로 남겼으며 공식 실험은 실행하지 않았다.

고정 수식과 누출 경계

exact float64 width 140, suffix [56:140], 시작점 (0,14,28,42,56), 길이 28·padding 없음, 평균 제거, 대칭 Hann 0.5-0.5*cos(2*pi*n/27), 길이-28 RFFT, DC 제외·Nyquist 포함 14 bin, bin당 1e-12, frame L1 정규화를 구현했다. 직접 DFT oracle과 atol=1e-15로 비교했고 level shift·양의 amplitude scaling 불변성, constant frame finite를 확인했다.

reference는 frame별 성분 중앙값 뒤 frame별 재정규화한다. fit raw는 자기 제외 LOO, query raw는 전체 fit만 사용한다. duplicate/tied median 수동 fixture와 query를 fit에 섞으면 raw가 달라지는 leakage fixture를 통과했다. 자연로그 JS의 다섯 frame 중앙값, <= rank, raw 0/equal max/nextafter above max confirmation 경계를 확인했다.

Review fix round 1

  • NumPy 단일 JS·batched raw와 Numba JS에서 승인 수식에 없던 1e-18/nonnegative clamp를 제거했다. 기대값 1.999998644061338e-20의 작은 양의 JS/raw가 그대로 남아 raw>0 confirmation 의미를 보존한다.
  • benchmark parent의 acceleration import를 제거했다. raw workload를 임시 NPZ로 전달한 clean child가 acceleration module·Numba import와 Hann/twiddle 생성 직전에 timer를 시작하며, backend 준비·cold compile·한 번의 warm 전체 실행·host 반환을 gate에 포함한다.
  • 실제 Numba direct-DFT primitive의 (5,14) power distribution을 NumPy RFFT oracle과 직접 rtol=0, atol=1e-12 비교해 bin order, DC 제거와 Nyquist 포함을 고정했다.
  • 세 회귀는 각각 RED를 확인한 뒤 GREEN으로 전환했고 focused suite는 17/17이다.

실제 10-fold workload와 backend
