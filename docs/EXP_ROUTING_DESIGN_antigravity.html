라우팅 달성 로드맵 (antigravity)

목표최종 목표 정의

이름·라벨 없이 데이터 자체 특징만 보고 최적 방법을 자동 선택하는 라우터

성공 기준: leave-one-family-out(LOFO) 검증에서 단일 최고 방법(single-best)보다 평균 성능 우수.
즉, 처음 보는 데이터셋 가족에 대해서도 라우터가 합리적 선택을 해야 함.

(config의 CANDIDATE_MATRIX)		새 데이터셋 대응 불가

설계핵심 설계 판단

1. 규칙 형태: 결정 트리

  • 해석 가능 — "width ≥ 500이면 Hydra 계열" 식으로 서술 가능
  • 디버깅 쉽고 오버피팅 위험 낮음
  • 논문·보고서 서술에 유리
  • 소형 학습 분류기는 8개 가족 수준에서는 오히려 불안정

2. 평가 축: AUC + FP≤10 TP 조합

  • AUC만 보면 전체 순위는 나오지만 실용성 부족
  • zero-FP TP는 일부 데이터셋(Yoga)에서 아예 신호가 안 잡힘
  • FP≤10 TP를 함께 보면 "실제 탐지량"을 반영

3. label-free 특징 후보 (4~6개로 시작)

특징정의기대 효과
width시퀀스 길이FordA/B(500) vs ECG(140) 구분
n_trainTRAIN majority 클래스 크기참조 밀도 판단
spectral_entropyFFT 파워 스펙트럼 엔트로피주기성 vs 무작위성

ref_score_var참조 점수 분산LocalGap 적합성

4. Exp471~473 결과 기반 초기 힌트

  • Yoga(width=426): raw C0 zero-FP 실패 → 보조 신호 필요
  • FordA/B(width=500): seed 민감 → 앙상블/평균화 필요
  • ECG200/5000: hydra_local_gap 우수
  • ElectricDevices: multirocket 계열 강세
  • ChlorineConcentration: minirocket_local_gap 강세

검증LOFO 프로토콜

  1. 8개 가족 중 1개 제외 (예: Yoga 빼고 나머지 7개로 규칙 학습)
  2. 제외된 Yoga에 규칙 적용 → 어떤 메서드 선택되는지 확인
  3. 실제 Yoga 최고 메서드와 비교 → 일치하면 성공
  4. 8번 반복해서 각 가족마다 한 번씩 제외하며 검증

리스크주요 리스크와 대응

리스크대응
가족 수 8개 → LOFO 검증 통계적 검증력 약함holdout 1개당 결정적 근거 확보. 단일 가족이라도 명확히 맞으면 의미 있음.
FordA/B seed 민감성특징 추출 시 seed별 평균값 사용. 라우팅 규칙 자체는 seed 독립적 특징만 사용.
Yoga처럼 zero-FP가 아예 안 되는 케이스FP≤10 축 병행. 라우팅은 "어느 방법이 상대적으로 낫다" 수준으로 판단.
Exp471~473 결과가 이미 이름 기반 편향 포함LOFO 검증에서 이름 정보를 완전히 배제하고 진행.
