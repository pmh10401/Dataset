Task 3 완료 범위와 승인 예외

  • local_stft_antigravity.py는 exact float64 width 140에서 suffix [56:140], 시작점 (0,14,28,42,56), 길이 28의 완전한 다섯 창만 사용한다.
  • 각 창은 평균 제거, 대칭 Hann 0.5-0.5*cos(2*pi*n/27), 길이-28 RFFT, DC 제외·Nyquist 포함 14 bin, bin당 1e-12, frame L1 정규화를 적용한다. 직접 DFT fixture가 NumPy oracle과 atol=1e-15로 일치한다.
  • fit raw는 각 행을 제외한 frame별 성분 중앙값 reference, query raw는 전체 fit reference를 사용한다. reference는 frame별 합 1로 재정규화한다. query를 fit에 섞는 leakage fixture와 duplicate/tied median fixture를 통과한다.
  • 자연로그 Jensen–Shannon의 다섯 frame 중앙값을 raw S10으로 사용한다. rank는 (1+count(fit_raw<=query_raw))/(n_fit+1), confirmation은 raw가 0과 fit 최댓값을 모두 엄격히 넘을 때만 true다.
  • 승인 수식에 없는 수치 clamp는 없다. 1.999998644061338e-20의 작은 양의 JS와 raw가 0으로 바뀌지 않고 strict confirmation의 raw>0 의미를 보존하는 회귀 검사를 통과한다.
  • 결과 배열은 finite exact float64/bool, shape, 최대값과 backend를 검증하고 소유 복사본을 read-only로 보존한다.

NumPy fallback 승인과 불변 선택 계약

승인 문서는 docs/superpowers/specs/2026-08-24-exp468-numpy-fallback-antigravity-design-amendment.html이며 SHA-256은 benchmark artifact의 fallback_authorization.approval_document_sha256에 기록한다. 승인 전 benchmark 전체 바이트 SHA-256 938d83b0319346270a6cc32b7b6ba3efb88122dc1bf431863d8030f4539fb63b도 함께 보존한다.

backend_selection_antigravity.py는 기존 AccelerationAssessmentAntigravity를 수정하지 않고 별도의 frozen decision을 만든다. 가속 성공을 주장하려면 선택 backend가 NumPy가 아니고 eligible, parity_passed, deterministic, speedup>=1.1을 모두 만족해야 한다. 실패 fallback은 모든 non-NumPy 후보의 비어 있지 않은 실패 이유와 64자리 lowercase 승인 SHA-256을 요구한다. 승인 없이 실패 assessment를 Task 4용으로 확정하면 PermissionError가 발생한다.

왜 Numba 또는 MPS 추가 최적화로 통과할 수 없는가

NumPy 기준 31.915ms에서 1.1배 빨라지려면 후보의 준비·컴파일·계산·반환 전체가 29.014ms 이하여야 한다. 그러나 Numba는 실제 계산과 컴파일을 시작하기 전 backend 준비만 100.190ms이며, warm 전체 실행도 32.608ms다. 따라서 준비 뒤 계산 시간이 0초라고 가정해도 이 gate를 통과할 수 없다.

Apple GPU와 현재 MLX/MPS runtime은 고정 수식에 필요한 float64/complex128 RFFT를 지원하지 않는다. float32 경로는 raw atol=1e-12를 보존할 수 없으며, GPU 초기화·전송 시간도 길이 28의 작은 frame 6,210개에서 회수되지 않는다. 이 결론을 뒤집으려면 동일 clean-process workload에서 모든 준비·전송·동기화를 포함한 총시간 29.014ms 이하, raw 오차 ≤1e-12, exact rank/confirmation, 반복 결정성을 동시에 새로 증명해야 한다.

승인 반영: 과학 수식과 결과 검증, gate와 허용오차를 그대로 유지하고 현재 가장 빠른 적격 경로인 NumPy CPU로 Task 4의 성능 평가를 진행한다. 이는 Numba 또는 MLX가 가속 gate를 통과했다는 뜻이 아니다.

Task 4 완료 범위 (보존된 과학·판정 계약)

  • scoring_antigravity.py는 checked Task 3 benchmark와 승인 문서 bytes를 읽어 immutable NumPy decision을 복원한다. 승인 SHA, 실패한 가속 gate, 승인 fallback, 선택 backend가 하나라도 다르면 Task 4 점수를 만들지 않는다. 공개 scorer에는 backend selector가 없다.
  • 각 fold에서 C0는 exact Exp466 adapter를 사용하고, normal과 네 합성 query를 한 combined NumPy S10 batch로 계산해 fit LOO calibration 하나를 공유한다. query는 reference에 들어가지 않는다.
  • FoldMethodScoresAntigravity는 C0/S10/C10, fit·query raw JS, strict confirmation, fit maximum, seed/fold, 원본 69×140 입력과 exact fit/query index, backend numpy를 소유한 C-contiguous read-only 배열로 보존한다.
  • C10은 confirmed에서만 max(C0,S10)이고 나머지는 C0와 array-equal이다. confirmation은 query_raw>0이면서 query_raw>max(fit_raw)인 strict 경계다.
  • blocked_fold_indices_antigravity()는 query 크기 (14,14,14,14,13)과 fit 크기 (55,55,55,55,56)의 exact public folds를 만든다. qualification은 fold 교환, seed-major order drift, OOF 누락·중복, TRAIN bytes drift를 replay 전에 거부한다.
  • qualification은 Task 4 assembler를 신뢰하지 않고 raw input에서 C0, 네 합성 scope, NumPy S10 raw/rank/confirmation, C10을 다시 계산해 exact equality를 요구한다. AUC는 각 fold의 normal query와 같은 fold·행의 변화 query 사이에서 mann_whitney_auc_antigravity(normal, changed)로 계산하며 pooled AUC나 mean gate를 만들지 않는다.
  • failure reason은 nonfinite_scores, period threshold, period strict C0 improvement, period confirmation, 세 보호 변화, normal confirmation 순서를 보존한다. evaluation은 10/10과 seed별 normal confirmation 0만 읽고 Task 5 private reproducibility 가능 여부를 표시하며 routing/champion/pending/promotion/TEST-label flag는 모두 false다.
