Exp455 구현 기록

Task 1은 planned-only governance surface를 만들었다. Task 2는 Exp454의 12개 고정 결과와 Exp446 stable-26, Exp404 Hard 좌표를 읽어 48개 immutable authority row와 8개 label-free 특징 row를 만들었다.

실제 source는 한 번만 읽었고 label_query_count=0이었다. TEST 정답은 읽지 않았으며, 특징에는 confusion, TP, FP, FN, TN, TEST label, 변형 번호 필드가 없다.

Task 3은 각 가족 안에서만 다른 데이터셋으로 규칙을 고르는 LODO 라우터를 추가했다. 규칙은 8개 정수 특징의 중간 경계와 양방향만 사용하며, 순서는 FN 최소, FP 최소, 정확한 Fraction F1 최대, candidate 사용 수 최소, 고정 lexical 순서다. held-out outcome을 바꿔도 해당 fold의 규칙과 선택은 변하지 않음을 테스트했다.

Task 4는 48개 행을 한 번씩 더해 baseline, 가족 전체 candidate, 데이터셋별 oracle, LODO router 네 비교를 계산한다. 결과 파일은 임시 주입 경로에만 8개 leaf로 저장하고, 다시 읽을 때는 규칙과 합계를 새로 계산한다. 파일 내용과 해시를 같이 바꿔도 계산값이 달라지면 거부한다.

Task 5는 evaluate --reviewed-commit <40 lower hex>와 bare inspect만 허용하는 닫힌 CLI를 추가했다. 합성 전체 흐름은 8 LODO fold, 48개 데이터셋, 네 비교, 8개 결과 leaf, label_query_count=0을 확인하고 replay 일치도 확인했다. Terra High와 agy Gemini 3.7 Flash High의 결과 중심 독립 검토는 모두 CLEAN이었다.

Task 6 공식 실행 결과

사용자 승인 뒤 clean commit b1ac9c24eea25b1da055d7076240d3058ffce613에서 공식 evaluate를 정확히 한 번 실행했다. 명령은 exit 1로 끝났고, ValueError: features must match authority targets in order가 발생했다.

원인은 label-free 특징의 승인 출력 순서(ECG5000 5개 → ChlorineConcentration 3개)와 Exp454 authority의 동결 원본 대상 순서(ChlorineConcentration → ECG5000)가 달랐기 때문이다. 실패는 성능 합산과 결과 폴더 생성 전에 발생했다. 공식 result root는 없고, TEST label 조회는 0회이며, 성공 조건이 아니므로 inspect는 0회다.

Exp455 상태는 official_evaluation_failed_immutable_no_retry다. FN·FP·F1 결과는 생성되지 않았고, routing/champion/pending candidate/promotion은 바뀌지 않았다. 이 순서 계약을 고치려면 Exp455 재실행이 아니라 새 실험 번호와 새 사전등록이 필요하다.
