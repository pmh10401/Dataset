## 목적

이 문서는 다른 Mac에서 현재 연구를 같은 코드, 같은 SQLite 데이터베이스,
같은 선행 점수원 결과로 이어가기 위한 절차다.

  "/Users/minho/Library/CloudStorage/GoogleDrive-pmh10401@gmail.com/내 드라이브/30_프로젝트_개발/timeseries-anomaly-research-handoff-20260728"

## Python 환경

Exp403-408 직접 의존성은 NumPy, scikit-learn, PyTorch다. 선행 실험과
대시보드까지 이어가려면 패키지에 기록된 환경 버전을 참고한다.

```bash
cd "/Users/minho/Documents/timesries project"
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install --upgrade pip
python3 -m pip install \
  numpy==2.3.5 scipy==1.17.1 scikit-learn==1.7.2 \
  pandas==2.3.3 torch==2.13.0
```

Apple Silicon용 PyTorch 설치 가능 버전이 달라진 경우에는 같은 major/minor를
우선 사용하고, 단위 테스트와 20개 대표 스모크를 반드시 다시 실행한다.

## 전체 실행 재개

기존 전체 checkpoint를 이어서 검증하려면 `--reset-checkpoint`를 사용하지 않는다.

> 2026-07-28 복원 검증 결과: 전달된 기준 커밋의 원본 코드로 계산한
> `input_sha256`도 보관 checkpoint의 값과 일치하지 않았다. 따라서 보관
> checkpoint와 최종 산출물은 해시 검증 후 review-only 근거로 사용할 수 있지만,
> 현재 브랜치에서 재계산 없는 직접 resume가 가능하다고 간주하면 안 된다.
> 생성 시점의 정확한 코드 provenance를 찾거나 새 실험 번호로 사전등록하기
> 전에는 아래 장시간 명령을 실행하지 않는다.

```bash
python3 scratch/run_exp403_408_feature_ml_validation.py \
  --stage all \
  --workers 7 \
  --device auto \
  --output-dir \
  "/Users/minho/Documents/Dataset/exp403_408_feature_ml_validation"
```

전체를 처음부터 재실행하려는 경우에만 별도 출력 폴더를 사용한다. 기존 결과를
덮어쓰지 않는다.

## 유지해야 할 연구 원칙

- prediction 단계에 TEST label과 실제 이상 위치를 전달하지 않는다.
- feature, score, calibration, threshold는 정상 TRAIN으로 결정한다.
- family별 과거 TEST 성능으로 source나 라우팅을 선택하지 않는다.
- `mean_combined_f1`은 human-assisted 지표로만 취급한다.
- Priority review와 Shadow 후보를 자동 경보로 승격하지 않는다.
- tail replacement를 재도입하지 않는다.
- TEST 결과를 보고 alpha, threshold, source, budget을 다시 선택하지 않는다.
- 새 가설은 새 실험 번호와 사전등록 문서로 분리한다.

## 알려진 제한

- 현재 저장소의 일부 과거 설정은 `/Users/minho/Documents/Dataset` 절대 경로를
  사용한다. 다른 macOS 사용자 계정을 쓰면 경로 호환 수정이 필요하다.
- Exp403-408은 retrospective 검증이다. 실제 설비 prospective validation 완료를
  의미하지 않는다.
- GitHub에는 DB와 대용량 결과를 올리지 않는다. 코드와 문서의 기준은 GitHub,
  데이터와 대용량 결과의 기준은 Google Drive 패키지다.
