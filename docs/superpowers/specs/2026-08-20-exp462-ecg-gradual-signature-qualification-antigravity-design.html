4. 24차원 gradual signature

각 길이 140 시계열에서 전체 [0:140], 앞 [0:70], 뒤 [70:140]의 세 view를 이 순서로 사용한다.

  1. 각 view에서 median을 빼고 1.4826 × MAD로 나눈다. scale이 0이거나 유한하지 않으면 실패한다.
  2. 길이 n의 고정 좌표 u = linspace(0, 1, n)를 만든다.
  3. 다섯 고정 basis를 만든다: 선형 u, 곡선 u², hinge ramp max(u-0.25,0), max(u-0.50,0), max(u-0.75,0).
  4. 각 basis에서 평균을 빼고 L2 norm으로 나눈 뒤 정규화 시계열과 내적한다. 이 다섯 값은 완만한 추세의 방향과 시작 위치를 나타낸다.
  5. view를 네 연속 구간으로 array_split하고, 인접 구간 median 차이 세 개를 계산한다.

view 하나당 5 + 3 = 8차원, 세 view 합계는 정확히 24차원이다. 출력은 유한한 float64, owned, C-contiguous, read-only 배열이다.

5. 점수와 순위

  • gradual 특징에는 Exp461과 동일한 TRAIN-only LocalGap 설정 k=3, alpha=0.005를 사용한다.
  • reference 점수 r 길이가 n일 때 query 점수 s의 이상 순위는 (1 + count(r_i ≤ s)) / (n + 1)이다.
  • Exp461 기준 점수는 reviewed Exp461 구현을 그대로 호출하며 복사하지 않는다.
  • 네 변화 유형과 생성 방식은 level_shift, gradual_drift, amplitude_scaling, period_change의 기존 frozen 정의를 그대로 사용한다.

6. 합격과 중단 조건

주 후보 hydra_period_gradual_rank_max만 다음 조건을 모두 만족해야 한다.

  • 10개 seed-fold 기록 모두 통과한다.
  • 각 기록의 네 변화 유형 AUC가 모두 0.85 이상이다.
  • 각 기록의 네 유형 평균 AUC가 0.90 이상이다.
  • 정상 오경보 Wilson 상한이 0.05 이하이고 모든 점수가 유한하다.
  • 10건 전체의 최소 gradual_drift AUC가 0.85 이상이며 Exp461 최소값 0.8402306222021025보다 엄격히 높다.
  • 10건 전체의 최소 period_change AUC가 Exp461 값 0.907392736783864 이상이다.
  • seed 20260721 fold 3의 period AUC가 0.907392736783864 이상이다.
  • seed 20261721 fold 4의 period AUC가 0.9216148584075248 이상이다.
중단 규칙: 하나라도 실패하면 공식 Exp462 평가를 실행하지 않는다. 특정 fold를 빼거나 기준을 낮추거나 가중치를 다시 고르지 않는다.
합격 시: 공식 결과를 바로 적용하지 않는다. 별도 승인 뒤 TRAIN-only 공식 qualification을 보존하고, 라우팅과 최종 FN/F1 평가는 다음 실험에서만 한다.

8. 구현과 검증 순서

  1. Task 1 — HTML preregistration, runbook, implementation report, dashboard, ledgers, code map을 만든다.
  2. Task 2 — Exp461 결과 권한과 동일 TRAIN/seed/fold/threshold 계약을 고정한다.
  3. Task 3 — 24차원 gradual signature와 세 방법 점수를 TDD로 구현한다.
  4. Task 4 — 30개 qualification 기록, 판정, 7개 파일, source-free replay를 구현한다.
  5. Task 5 — CLI를 닫고 실제 TRAIN 비공식 evaluate→inspect를 순차 두 번 재현한 뒤 fresh review를 받는다.
  6. Task 6 — Task 5가 모든 조건을 통과하고 사용자가 별도 승인한 경우에만 공식 결과를 한 번 보존한다.

완료된 Task/Step의 HTML 체크박스는 검토가 끝난 뒤에만 체크한다. Task 6 승인 전에는 official evaluate/inspect가 모두 0이어야 한다.

9. CPU와 MLX

24차원 고정 projection은 MLX 표현이 가능하므로 전체 실행 전 동일 입력·seed CPU/MLX smoke를 한다. finite 결과, 후보 순서 일치, 수치 허용오차, 전송·동기화 포함 1.1배 속도 조건을 모두 만족할 때만 MLX를 사용한다. 현재 Exp461 고정 interpreter에는 MLX가 없었으므로 설치하지 않고, 다시 확인해 unavailable이면 CPU NumPy를 유지한다.
