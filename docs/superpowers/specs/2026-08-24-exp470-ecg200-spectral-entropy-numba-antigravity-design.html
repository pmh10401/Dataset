Exp470 ECG200 spectral entropy Numba 설계서

설계 상태: 작성된 HTML 설계서 사용자 승인 완료.

한 줄 요약: Exp468이 사용한 같은 STFT에서 주파수 에너지가 얼마나 퍼져 있는지만 한 가지 새 점수로 계산하고, Numba 결과가 작은 Python math 기준 검사와 결정성 검사를 통과할 때만 TRAIN-only 자격 검증을 진행한다.

1. 왜 새 실험을 하는가

Exp468은 두 번 실행한 결과가 파일 7개 모두 바이트 단위로 같아 계산 재현성은 확인됐다. 그러나 C10은 10개 seed-fold 중 0개만 통과했다. 8개 fold는 C0와 같았고, 두 fold의 작은 개선은 seed별 정상 오확인 1개와 함께 발생했다.

Exp470은 Exp468의 임계값을 다시 조정하지 않는다. 같은 power spectrum에서 분포 전체의 모양을 비교한 JS 대신, 에너지가 몇 개 주파수에 몰렸는지 또는 넓게 퍼졌는지를 나타내는 spectral entropy 하나만 검증한다.

3. 고정 입력

  • ECG200 TRAIN 정상 +1 69개만 사용한다.
  • Exp468과 같은 방법으로 길이 96→140을 선형 보간한다.
  • seed는 20260721, 20261721, seed당 blocked fold 5개다.
  • suffix는 [56:140], 길이는 84다.
  • 시작점 (0,14,28,42,56)에서 길이 28인 창 다섯 개를 사용한다.
  • 대칭 Hann은 w[n]=0.5-0.5*cos(2*pi*n/27)이다.
  • DFT 길이는 28이며 DC를 제외한 14개 bin, float64, epsilon 1e-12, 자연로그를 사용한다.
  • level shift, gradual drift, amplitude scaling, period change는 Exp468의 exact authority를 그대로 사용한다.

4. spectral entropy 점수

각 창의 DC 제외 power를 P[k]라 하고, 합이 1이 되게 만든 비율을 p[k]라 한다.

p[k] = (P[k] + 1e-12) / sum_j(P[j] + 1e-12)
H(window) = -sum_k(p[k] * log(p[k])) / log(14)
h(row) = median(H(window_1), ..., H(window_5))

H가 작으면 일부 주파수에 에너지가 몰렸고, 크면 여러 주파수에 넓게 퍼졌다는 뜻이다. 방향을 결과를 보고 고르지 않기 위해 정상 중심에서 떨어진 절댓값을 raw 점수로 쓴다.

fit_raw[i] = abs(h(fit[i]) - median(h(fit without i)))
query_raw = abs(h(query) - median(h(fit)))
E11_rank = (1 + count(fit_raw <= query_raw)) / (n_fit + 1)
confirmed = query_raw > 0 and query_raw > max(fit_raw)
C11 = max(C0, E11_rank) if confirmed else C0

SNR, phase trajectory, DTW, recurrence, period variance를 같은 실행에 넣지 않는다. 후보를 여러 개 시험한 뒤 가장 좋은 것을 고르는 선택편향을 막기 위해 Exp470의 새 점수는 spectral entropy 하나뿐이다.

5. 잔여 구조 개선 판정

C0에는 고정된 이진 경보선이 없으므로 “C0가 놓친 행”이라는 새 임계값을 만들지 않는다. 대신 AUC를 이루는 모든 정상–변화 점수 쌍의 순서가 좋아졌는지 직접 센다.

pair_credit(normal, changed) = 1.0 if changed > normal
                             = 0.5 if changed == normal
                             = 0.0 if changed < normal

fixed  = count(C11_credit > C0_credit)
broken = count(C11_credit < C0_credit)

같은 blocked 구간을 쓰는 두 seed는 독립 표본처럼 더하거나 p값을 만들지 않는다. 각 seed를 반복 확인으로 보고 아래 조건을 각각 만족해야 한다.

  1. 모든 값이 finite다.
  2. 각 seed의 period fixed 합이 0보다 크다.
  3. 각 seed의 period broken 합은 0이다.
  4. level shift, gradual drift, amplitude scaling의 broken 합은 모두 0이다.
  5. 두 seed의 OOF 정상 confirmation 합은 각각 0이다.
  6. confirmation이 false인 모든 위치에서 C11과 C0는 dtype·shape·bytes가 같다.
  7. 서로 다른 두 private root의 canonical 결과 파일과 최종 판정이 byte-identical이다.

AUC와 기존 0.85 기준은 설명용으로 기록하지만 합격 조건으로 사용하지 않는다.

6. Numba 구현 계약

  • Numba의 np.fft.rfft 지원에 기대지 않는다. 길이 28의 고정 cosine/sine 표를 사용하는 float64 direct DFT부터 entropy, LOO 중앙값, raw, rank, confirmation, C11 결합, pair count까지 njit로 구현한다.
  • 별도 NumPy scorer를 만들지 않는다. 작은 고정 입력만 Python math.fsum, cos, sin으로 같은 계산을 재현해 독립 기준값으로 사용한다. 이 기준 코드는 전체 데이터 scoring에 참여하지 않는다.
  • Numba는 finite, Python 기준 대비 raw 최대 오차 ≤1e-12, exact rank, exact confirmation, exact fixed/broken count, 반복 결정성을 모두 만족해야 한다.
  • 기준 검사나 결정성이 실패하면 실험을 중단한다. 다른 backend로 자동 전환하지 않는다.
  • cold compile 시간, warm 평가 시간, Python·Numba·llvmlite 버전과 CPU 정보를 manifest에 기록한다. 속도는 관측값이며 Exp470 성능 합격 기준은 아니다.
  • 새 score-source 전체 실행 전 MLX smoke를 별도로 수행한다. Numba와 같은 입력·seed에서 raw ≤1e-12, exact 후보 index, 결정성, 전송·동기화 포함 1.1배를 모두 통과할 때만 적격으로 기록한다. 사용자 승인 backend는 Numba이므로 MLX는 Exp470 공식 계산을 대신하지 않는다.
  • MLX/MPS-heavy process는 한 번에 하나만 실행한다.

7. 실패와 중단

  • Numba 설치·컴파일·Python 기준 검사·결정성 중 하나라도 실패하면 STOP한다.
  • 정상 confirmation이 한 건이라도 생기면 FAIL로 보존한다.
  • period fixed가 어느 seed에서든 0이면 FAIL이다.
  • period 또는 보호 변화에서 broken pair가 한 건이라도 생기면 FAIL이다.
  • 실패 뒤 같은 Exp470에서 entropy 집계, epsilon, 창, onset, threshold, seed, fold, 합격 기준을 바꾸지 않는다.
  • private 결과가 통과해도 별도 승인 전에는 official 실행, TEST/FN 확인, routing을 하지 않는다.

8. 검증과 결과물

  • 수식, entropy 범위·유한성, LOO 분리, strict 경계, exact C0 fallback을 단위 테스트한다.
  • 작은 고정 입력의 Python math–Numba 기준 검사와 두 번의 결정성 검사를 수행한다.
  • C0/E11/C11 raw evidence, pair credit, fixed/broken, AUC와 판정을 source-free replay할 수 있게 보존한다.
  • 결과 문서와 대시보드는 항상 HTML로 작성하며, 완료 task의 체크박스는 항상 체크한다.
  • 공식 실행 전 private 실행 1·2는 사용자의 별도 checkpoint 승인을 받는다.
