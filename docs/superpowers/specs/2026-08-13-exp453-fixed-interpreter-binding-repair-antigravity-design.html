Exp453: 고정 Python 실행 경로 복구 설계

한 줄 요약: Exp452의 계산식이나 데이터가 잘못된 것이 아니다. 공식 명령을 다른 Python 환경으로 실행해 시작 검사에서 멈췄다. Exp453는 세 공식 명령이 반드시 올바른 Python 환경에서 실행되도록 고친다.

확인된 사실
  • Exp452 readiness는 1회 실행되어 실패했고, evaluate와 inspect는 실행되지 않았다.
  • TEST label은 한 건도 읽지 않았고 성능 결과도 만들어지지 않았다.
  • 잘못 사용한 Python 환경에는 NumPy 2.4.6이 있었다.
  • 원래 고정한 환경에는 Python 3.14.6, NumPy 2.3.5, aeon 1.4.0, scikit-learn 1.7.2가 정확히 설치되어 있다.
  • Exp452는 재실행하지 않는다. 새 실험 Exp453에서만 복구한다.

1. 원인

Python 가상환경은 서로 다른 패키지 묶음이다. 두 가상환경이 같은 기본 Python 파일을 공유하더라도 NumPy 같은 패키지 버전은 다를 수 있다.

Exp452 공식 실행은 아래의 올바른 경로가 아니라 다른 가상환경으로 시작됐다.

/Users/mac/Documents/Dataset/venvs/detection-coverage-antigravity-aeon140-py314/bin/python

그 결과 readiness가 NumPy 버전 차이를 발견하고 중단했다. 이는 과학 성능 실패가 아니라 실행 환경 선택 실패다.

2. 비교한 해결 방법

방법판단
Exp452를 올바른 Python으로 다시 실행사용하지 않는다. Exp452는 이미 공식 1회 규칙에 따라 종료됐다.
NumPy 2.4.6으로 과학 환경 변경사용하지 않는다. 불필요한 수치 환경 변경이 생긴다.
Exp453에서 고정 Python 경로 결속선택. 기존 과학 환경과 계산을 그대로 유지하는 가장 작은 복구다.

3. 선택한 구조

Exp453 launcher는 Exp453 모듈을 불러오기 전에 현재 실행 환경을 확인한다.

  1. sys.executable의 절대 문자열이 고정 venv의 Python 경로와 같은지 확인한다.
  2. sys.prefix가 고정 venv 경로와 같은지 확인한다.
  3. 다른 환경이면 고정 Python으로 launcher를 딱 한 번 다시 시작한다.
  4. 다시 시작한 뒤에도 경로가 다르면 즉시 실패한다.
  5. Python, NumPy, aeon, scikit-learn 버전이 모두 고정값과 같은지 확인한다.

Path.resolve()나 samefile()만으로 판단하지 않는다. 서로 다른 venv가 같은 기본 Python 파일을 가리킬 수 있기 때문이다.

이 규칙은 readiness, evaluate, inspect 세 명령에 똑같이 적용된다.

7. 결과 동일성 테스트

  1. 잘못된 Python으로 launcher를 시작하면 Exp453 모듈 import 전에 고정 Python으로 한 번 전환되는지 확인한다.
  2. 고정 Python으로 직접 시작하면 다시 실행하지 않는지 확인한다.
  3. 세 명령 모두 같은 Python 경로와 같은 네 패키지 버전을 사용하는지 확인한다.
  4. 같은 Exp449 prediction bytes와 같은 synthetic label을 Exp452와 Exp453 평가기에 넣는다.
  5. 12개 artifact의 정규화된 내용이 모두 같은지 확인한다. 차이를 허용하는 항목은 실험 이름, 경로, reviewed commit, 그 값에서 파생된 SHA, runtime-binding 기록뿐이다.
  6. 96개 index list가 작은 값부터 정렬되어 있고 prediction과 순서까지 같은지 확인한다.
  7. confusion, FN, FP, F1, bootstrap draw와 decision이 정확히 같은지 확인한다.

8. 오류 처리

  • 고정 Python으로 전환할 수 없거나 버전이 다르면 label을 읽기 전에 중단한다.
  • Exp452 failure evidence 또는 Exp449 prediction이 다르면 label을 읽기 전에 중단한다.
  • 공식 readiness 또는 evaluate가 실패하면 Exp453도 재시도하지 않는다.
  • evaluate 성공과 독립 결과 검증이 끝난 경우에만 inspect를 한 번 실행한다.

9. 공식 성공 기준

  • 공식 세 명령이 모두 고정 interpreter에서 실행된다.
  • Label session 1회, 48개 ordered query, 72,300개 row가 정확하다.
  • 96개 prediction과 evidence index list가 순서까지 정확히 같다.
  • 12개 artifact와 artifact SHA map이 source-free replay를 통과한다.
  • 기존 FN·FP·F1 기준을 그대로 적용한다.
  • 동일 실험 안에서 후보, threshold, routing을 다시 선택하지 않는다.
범위 제한: Exp453는 실행 환경 결속만 고친다. 보안·운영 기능을 추가하지 않고, 성능 결과에 영향을 주는 검증만 구현한다. Dashboard는 성공 결과 closeout 이후 별도 단계에서 aggregate 결과만 사용한다.

10. 구현과 검토

  1. HTML 사전등록·실행 안내·계획과 Exp453 code map을 만든다.
  2. Exp452 controlled fork에 고정 interpreter launcher 경계와 두 predecessor gate를 추가한다.
  3. Grok CLI grok-4.6, reasoning high가 구현한다.
  4. 각 구현 단계와 최종 후보는 fresh Sol high가 결과 중심으로 검토한다.
  5. 사용자 승인 후 official lifecycle을 각각 한 번 실행한다.

11. 결론

Exp453는 새 과학 방법을 시험하지 않는다. 이미 준비된 올바른 Python 환경을 공식 명령에 확실히 연결해, Exp452에서 시작조차 못 한 성능 평가를 같은 계산 조건으로 수행하는 최소 복구 실험이다.
