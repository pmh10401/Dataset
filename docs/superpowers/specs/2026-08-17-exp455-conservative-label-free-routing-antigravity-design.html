1. 왜 새 실험이 필요한가

Exp454에서는 다음 두 가족·기법 조합이 전체 성능 기준을 통과했다.

ECG5000 + Hydra LocalGap1,9873130.626745−1
ChlorineConcentration + MultiRocket LocalGap1,9873120.626846−1

하지만 가족 안의 모든 데이터셋이 좋아진 것은 아니다. ECG5000의 한 변형은 FN이 6개 늘었고, ChlorineConcentration의 다른 변형은 FN 또는 FP가 늘었다. 따라서 가족 이름만 보고 항상 LocalGap을 적용하면 안 된다.

2. 승인된 범위

  • 실험 번호는 Exp455다.
  • 후보는 정확히 두 개다: ECG5000의 Hydra LocalGap, ChlorineConcentration의 MultiRocket LocalGap.
  • 대상은 두 가족의 8개 변형이다: ECG5000 5개, ChlorineConcentration 3개.
  • 나머지 40개 데이터셋은 baseline 결과를 그대로 유지한다.
  • 근접 탈락 기법, 새 모델, 새 점수원, 자동 승격은 이번 범위에 넣지 않는다.

3. 라우터가 보는 정보

라우터는 TEST 정답을 입력으로 사용하지 않는다. 각 데이터셋에서 다음 값만 본다.

  1. 데이터 길이
  2. baseline이 이상으로 표시한 위치의 수
  3. LocalGap 후보가 이상으로 표시한 위치의 수
  4. 두 예측이 함께 표시한 위치의 수와 겹침 비율
  5. 후보가 새로 추가한 위치 수와 baseline에서 제거한 위치 수
  6. 가족 이름: ECG5000 또는 ChlorineConcentration

baseline 위치는 기존 Exp404 Hard와 Exp446 stable-26 예측에서 다시 구성한다. LocalGap 위치는 Exp454의 동결된 frozen_predictions_antigravity.jsonl을 사용한다. 이 단계는 새 점수를 계산하지 않는다.

4. 라우팅 방법

복잡한 모델 대신 깊이 1의 결정 규칙만 사용한다. 예를 들면 “후보가 baseline보다 새 위치를 3개 이하 추가하면 LocalGap을 사용한다”와 같은 한 가지 조건의 규칙이다.

  1. 한 데이터셋을 검증용으로 빼 둔다.
  2. 나머지 데이터셋에서 가능한 단순 규칙을 비교한다.
  3. FN이 가장 작은 규칙을 고른다. 동률이면 FP가 작은 규칙, 다시 동률이면 baseline을 더 많이 유지하는 규칙을 고른다.
  4. 빼 둔 데이터셋에 고른 규칙을 적용한다.
  5. 8개 데이터셋을 각각 한 번씩 빼면서 반복한다.

각 숫자 특징은 학습용 데이터에서 관측된 값 사이의 중간점을 기준 후보로 사용한다. 각 후보에 대해 기준 이하와 기준 초과 방향을 모두 비교하며, 항상 baseline과 항상 LocalGap도 비교 목록에 포함한다.

이 방식은 검증 대상의 정답을 규칙 선택에 직접 사용하지 않는 leave-one-dataset-out 평가다.

6. 성능 통과 기준

8개의 제외 검증 결과를 합친 뒤, 나머지 40개 baseline 결과와 결합해 전체 48개 데이터셋 성능을 계산한다.

  • ☐ 주요 기준: 전체 FN이 1,988보다 작다.
  • ☐ FP 안전 기준: 전체 FP가 314 이하이다.
  • ☐ F1 안전 기준: 전체 F1이 0.6264199935 이상이다.
  • ☐ ECG5000과 ChlorineConcentration 각각의 합산 FN이 해당 가족 baseline보다 나쁘지 않다.
  • ☐ 라우터 입력에 TEST 정답, confusion 값, 데이터셋 변형 번호를 넣지 않는다.

모든 기준을 통과하면 상태는 routing_candidate_qualified_for_external_validation이다. 이는 새 데이터에서 다시 검증할 자격만 뜻하며 자동 라우팅이나 모델 승격을 뜻하지 않는다.

7. 결과 계산

  1. Exp454의 12개 결과 파일과 세 핵심 SHA-256을 읽기 전용으로 확인한다: artifact map 748fdc62de555279640b4ce588b3155670ebe33e13e5997d40061d96011bff65, evaluation c2b6321d18ba4c98e426be96ea3d3fb0824e75926fa54ba4600634dded68e1ac, decision 3510a426d3ee083ccb3f8599c64d0c91cc56d0b902780c8b6a2136098cd9a595.
  2. 8개 대상 데이터셋의 label-free 특징을 만든다.
  3. leave-one-dataset-out 방식으로 8개의 선택 결과를 만든다.
  4. Exp454에 저장된 데이터셋별 confusion으로 선택 결과의 FN, FP, TP, TN을 합한다.
  5. F1과 가족별 FN 변화를 계산하고 통과 여부를 결정한다.
  6. 같은 입력으로 다시 계산했을 때 모든 선택과 결과가 같아야 한다.

8. 결과 파일과 대시보드

설계, 계획, 구현 기록은 모두 HTML로 작성한다. 결과는 최소한 다음 내용을 남긴다.

  • 8개 데이터셋의 label-free 특징과 제외 검증에서 선택된 경로
  • baseline, 가족 전체 적용, 정답 기반 상한선, 실제 라우터의 FN·FP·F1
  • 가족별 FN 변화와 최종 통과 여부
  • 재계산에 필요한 고정 설정과 결과 해시

대시보드는 진행 중에는 완료 데이터셋 수와 현재 단계를, 완료 뒤에는 네 방법의 FN·FP·F1 및 가족별 FN 변화만 보여준다. 원시 TEST 라벨이나 개별 위치 목록은 표시하지 않는다.

9. 해석 범위

Exp455는 Exp454 결과에서 선택된 두 기법을 같은 8개 변형 안에서 제외 검증한다. 따라서 통과하더라도 “새 데이터에서도 반드시 좋아진다”는 증거는 아니다. 결론은 새 데이터 검증에 올릴 수 있는 간단한 라우팅 후보가 생겼다로 제한한다.

10. 구현 전 체크리스트

  • ☐ Exp454 결과 root와 artifact/evaluation/decision SHA-256을 설계 기준으로 고정한다.
  • ☐ 두 가족·두 기법·8개 데이터셋 외 후보를 추가하지 않는다.
  • ☐ 특징 계산 코드와 정답 기반 평가 코드를 분리한다.
  • ☐ 단순 규칙의 후보와 동률 처리 순서를 구현 전에 고정한다.
  • ☐ 모든 문서와 진행·결과 화면을 HTML로 만든다.
