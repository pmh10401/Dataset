Exp471 — ECG200 ACF peak-lag 이동 Numba 자격 검증

설계 상태: 사용자가 이 고정안을 검토·승인했고, HTML 구현 계획까지 작성했다.

한 줄 목표: 파형 앞부분과 뒷부분에서 반복 간격이 얼마나 달라졌는지 한 개의 자기상관 점수로 재고, C0가 놓친 period 순서만 안전하게 고칠 수 있는지 확인한다.

1. 왜 이 실험을 하는가

Exp470의 두 private 실행은 완전히 같았지만, 두 seed 모두 period fixed=0이었다. spectral entropy가 확인한 period 행은 이미 C0 점수가 1.0이어서 실제 수정으로 이어지지 않았다. 따라서 임계값을 낮추지 않고, 합성 period 변화가 만든 반복 간격의 이동을 직접 측정한다.

과거 Exp461 계열은 여러 FFT·자기상관 값을 한꺼번에 거리로 합쳤다. Exp471은 그 방법을 다시 조정하지 않는다. 앞·뒤 구간의 대표 반복 간격 차이 하나만 남겨, 정보가 여러 특징 사이에서 약해졌는지를 확인한다.

3. 앞·뒤 구간을 고르는 규칙

구간좌표이유

뒤 구간[84:140]변화 시작 경계를 피하면서 앞 구간과 같은 길이 56을 유지한다.

각 구간은 중앙값을 빼고 1.4826 × MAD로 나눈다. MAD가 0 이하이거나 결과가 유한하지 않으면 즉시 STOP한다. 이 표준화 때문에 단순한 높이 이동과 양의 크기 배율은 ACF 모양을 바꾸지 않아야 한다.

4. ACF peak-lag 한 개를 만드는 방법

표준화한 길이 56 구간을 z라 하고, lag 1부터 25까지 아래 자기상관을 계산한다.

ACF(lag) = sum(z[t] * z[t + lag]) / sum(z[t] * z[t])
           t = 0 .. 55-lag             t = 0 .. 55

peak 후보 lag = 2 .. 24 중에서
  ACF(lag) > 0
  ACF(lag) > ACF(lag-1)
  ACF(lag) >= ACF(lag+1)

dominant_peak = ACF가 가장 큰 peak 후보의 lag
                동점이면 더 작은 lag
                후보가 없으면 0

lag 1과 25는 양쪽 이웃이 없어서 peak 후보에서 제외한다. 최대 lag 24는 이전 자기상관 실험의 고정 범위를 그대로 사용하며, Exp471 결과를 보고 바꾸지 않는다.

early_peak = dominant_peak(row[0:56])
late_peak  = dominant_peak(row[84:140])
shift(row) = late_peak - early_peak

shift는 앞보다 뒤의 반복 간격이 몇 칸 이동했는지 나타낸다. peak의 0은 실제 lag 2..24와 겹치지 않는다. 다만 두 peak가 같아 생긴 shift 0과 두 구간 모두 peak가 없어 생긴 shift 0은 같은 “이동 근거 없음”으로 일부러 합친다. peak 존재 여부와 선택된 lag는 설명 자료로 저장하지만 점수에는 쓰지 않아, 후보 수는 하나로 유지한다.

5. E12와 C12

방향을 결과를 보고 고르지 않기 위해, 정상 TRAIN의 대표 shift에서 얼마나 멀리 떨어졌는지를 raw 점수로 사용한다.

fit_raw[i] = abs(shift(fit[i]) - median(shift(fit without i)))
query_raw  = abs(shift(query)  - median(shift(fit)))

E12_rank = (1 + count(fit_raw <= query_raw)) / (n_fit + 1)
confirmed = query_raw > 0 and query_raw > max(fit_raw)
C12 = max(C0, E12_rank) if confirmed else C0

median은 값을 오름차순으로 정렬한 뒤 홀수 개면 가운데 값, 짝수 개면 가운데 두 값의 산술평균으로 고정한다. blocked fold의 query index는 fit 목록에 들어가지 않으며, query shift는 fit median이나 fit raw를 만드는 데 한 번도 사용하지 않는다. fit 행의 raw만 자기 자신을 뺀 나머지 fit 행으로 계산한다.

C0와 E12는 모두 범위 (0,1]의 순위 점수라 같은 척도에서 비교한다. Exp471은 Exp470의 exact C0 scorer와 결합 규칙을 import한다. 확인이 됐더라도 E12가 C0보다 크지 않으면 C12는 C0 그대로다. confirmation이 거짓인 모든 위치에서는 C12의 dtype, shape와 bytes가 C0와 같아야 한다.

FFT, spectral entropy, DTW, phase margin, recurrence, 여러 lag 범위나 여러 창 조합을 함께 시험하지 않는다. Exp471의 새 후보는 위 ACF shift 하나뿐이다.

6. 잔여 FN 구조 개선 판정

AUC의 바탕이 되는 정상–변화 점수 쌍을 직접 비교한다.

pair_credit(normal, changed) = 1.0  if changed > normal
                             = 0.5  if changed == normal
                             = 0.0  if changed < normal

fixed  = count(C12_credit > C0_credit)
broken = count(C12_credit < C0_credit)

두 seed는 독립 표본처럼 합쳐 p값을 만들지 않고 반복 확인으로 본다. 다음 조건을 모두 만족해야 PASS다.

  1. 모든 ACF, raw, rank와 결합 점수가 finite다.
  2. 각 seed의 period fixed 합이 1개 이상이다.
  3. 각 seed의 period broken 합은 0개다.
  4. level shift, gradual drift, amplitude scaling의 broken 합은 모두 0개다.
  5. 각 seed의 OOF 정상 confirmation 합은 0개다.
  6. fallback 구간에서 C12와 C0가 byte 단위로 같다.
  7. 서로 다른 두 private root의 canonical 결과 7개와 최종 판정이 byte 단위로 같다.

AUC는 설명용으로 기록하지만 0.85를 합격선으로 사용하지 않는다.

7. Numba·MLX 계산 계약

  • 중앙값, MAD, ACF, peak 선택, LOO raw, rank, confirmation, C12 결합과 pair count의 새 숫자 경로를 Numba njit로 구현한다.
  • 작은 고정 입력은 Python math.fsum과 sorted로 별도 재현한다. 이 기준 코드는 전체 데이터 점수 계산에 참여하지 않는다.
  • Numba는 Python 기준 대비 ACF·raw 최대 오차 ≤1e-12, exact peak lag, exact rank, exact confirmation, exact fixed/broken count와 반복 결정성을 만족해야 한다.
  • Numba 기준 검사나 결정성이 실패하면 실험을 중단한다. NumPy scorer로 전환하지 않는다.
  • 새 점수 전체 실행 전 같은 입력과 seed로 MLX 적격성 smoke를 수행한다. finite, 수치 오차 ≤1e-12, exact peak lag·confirmation, 결정성과 전송·동기화 포함 1.1× 속도를 모두 기록한다.
  • Exp471의 승인 backend는 Numba다. MLX smoke는 적격성 근거만 남기며 이 실행의 점수 authority를 바꾸지 않는다.
  • Python, Numba, llvmlite, MLX와 mlx-metal 버전, CPU/GPU, cold compile·warm 평가 시간을 manifest에 기록한다.

8. 구현 검증 항목

  • 좌표 [0:56], [84:140]와 lag 1..25가 한 칸도 바뀌지 않는지 검사한다.
  • 양수 peak, 동점의 작은 lag 우선, peak 없음의 0 sentinel을 단위 테스트한다.
  • 상수 더하기와 양의 상수 곱하기가 peak와 shift를 바꾸지 않는지 검사한다.
  • 고정된 작은 time-stretch 예제에서 late peak가 예상한 lag로 이동하는지 검사한다.
  • LOO 분리, strict > 경계, rank tie, C0 exact fallback을 검사한다.
  • 저장된 raw evidence만으로 E12/C12, pair repair, AUC와 판정을 다시 만들 수 있어야 한다.

9. 실패와 중단 규칙

  • 위 PASS 조건 하나라도 실패하면 Exp471 결과를 FAIL로 그대로 보존한다.
  • 실패 뒤 같은 Exp471에서 창 좌표, lag 범위, peak 규칙, sentinel, 집계, threshold, seed, fold 또는 합격 기준을 바꾸지 않는다.
  • 결과를 본 뒤 signed shift, 절댓값 shift 또는 다른 ACF 정규화 중 좋은 것을 고르지 않는다. 승인된 식만 실행한다.
  • private 실행 1·2는 구현과 사전검증이 끝난 뒤 별도 승인을 받아 순차 실행한다.
  • private 결과가 PASS여도 별도 승인 전에는 official 실행, TEST/FN 확인과 routing을 하지 않는다.
