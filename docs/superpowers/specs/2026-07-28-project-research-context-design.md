# 현재 프로젝트 연구 맥락 통합 문서 설계

Date: 2026-07-28
Status: approved design, not implemented
Audience: 연구 책임자, 후속 개발자, 미래 Codex 작업

## 1. 목적

현재 저장소에는 초기 VAE 연구, 데이터 품질 감사, 다수의 후속 실험,
Exp403-408 동결 결과, Exp409 준비성 검증이 서로 다른 시점의 문서로 남아
있다. 각 문서는 해당 시점의 근거로 유효하지만, 오래된 전제와 현재의 결론을
한 번에 구분할 수 있는 공식 입구가 없다.

새 통합 문서 `docs/PROJECT_RESEARCH_CONTEXT_KO.md`를 만들어 다음을
명확하게 한다.

- 프로젝트가 해결하려는 실제 문제와 성공 기준
- 현재 데이터의 성격, 한계, 사용 가능한 검증 범위
- 연구가 현재의 보수적인 lane 구조에 도달한 과정
- Exp403-409의 위치와 현재 동결 기준선
- 허용되는 성능 주장과 금지되는 해석
- 신규 실데이터가 영구적으로 없다는 조건에서의 후속 연구 방향
- 목적별로 읽어야 할 핵심 근거 문서

이 문서는 과거 실험 계약을 소급해 변경하는 문서가 아니라, 기준일 현재
프로젝트 전체를 해석하는 최상위 안내서다.

## 2. 범위와 비범위

### 포함 범위

- 2026-07-28 현재의 연구 배경과 의사결정 기준
- UCR 기반 현 벤치마크 데이터와 반도체 현장 적용 목표의 구분
- 신규 실데이터를 받을 수 없는 영구적인 운영 제약
- 현재 동결 lane과 Exp403-409 결과의 의미
- 반복 실험과 감사에서 확인된 데이터·평가 위험
- 이후 실험에 적용할 누수 방지, 사전등록, 주장 경계
- 근거 문서 간 우선순위와 알려진 문서 결손

### 제외 범위

- 모델, 임계값, source, alpha, review budget 또는 lane 변경
- 새로운 성능 실험의 설계나 실행
- 과거 문서와 수치의 소급 수정
- Exp409를 실제 prospective 성능 검증으로 재해석하는 행위
- 현재 벤치마크 결과를 반도체 현장 성능으로 일반화하는 주장
- 오래된 `README.md`의 전면 개편

통합 문서 작성은 문서화 작업일 뿐, 운영 정책이나 동결 산출물을 변경하지
않는다.

## 3. 대상 독자와 문서 지위

주요 독자는 다음 세 집단이다.

1. 연구 책임자: 현재까지의 근거와 다음 연구의 정당성을 빠르게 판단한다.
2. 후속 개발자: 금지된 누수와 변경 불가 항목을 이해한 뒤 구현한다.
3. 미래 Codex 작업: 오래된 문서만 읽고 이미 폐기된 방향을 재개하지 않도록
   현재의 기준점을 복원한다.

문서 첫머리에 다음 지위를 명시한다.

- 기준일: 2026-07-28
- 역할: 현재 프로젝트 해석을 위한 공식 입구
- 역사적 실험 계약의 대체 여부: 대체하지 않음
- 성능 근거 생성 여부: 생성하지 않음
- 현재 전제: 신규 반도체 실데이터의 추가 확보 및 외부 반출은 불가능

## 4. 문서 구조

통합 문서는 아래 순서로 작성한다.

### 4.1 프로젝트가 해결하려는 문제

목표를 단일 mean F1 최대화로 표현하지 않는다. 정상 TRAIN 데이터만으로
후보를 만들고 false alarm을 억제하여 사용자의 경보 신뢰를 높이는 것이
핵심임을 먼저 설명한다.

### 4.2 데이터의 실제 성격과 제약

현재 SQLite 데이터는 반도체 설비에서 반출된 원본 데이터가 아니라 UCR Time
Series Archive의 one-vs-all 구성과 CornellWhaleChallenge 계열로 만들어진
연구용 벤치마크임을 명시한다. 현재 연구 모집단이 1,117개 데이터셋으로
동결된 배경도 기록한다.

반도체 설비가 최종 적용 대상이라는 사실과 현재 벤치마크의 출처를 혼동하지
않도록 두 역할을 분리한다.

### 4.3 데이터셋 위험 요소

다음 위험을 쉬운 설명과 함께 요약한다.

- 작은 TRAIN과 TEST 표본
- 단 하나의 이상 샘플에 의존하는 평가
- 정상 TRAIN/TEST의 높은 정확 중복
- one-vs-all 구성으로 인한 family 내부 중복
- instance label과 시점별 이상 위치의 차이
- 가변 길이 메타데이터 불일치
- model-hard와 evaluation-hard의 구분

수치는 감사 보고서에서 직접 확인되는 것만 사용하고 출처를 붙인다.

### 4.4 연구 발전 과정

초기 VAE 중심 탐색을 현재 성과로 제시하지 않고 역사적 출발점으로 둔다.
그 후 전역 교체, 후보 합집합, family별 표현, review-only 분리,
Exp403-408 feature/ML 검증, Exp409 준비성 거버넌스로 이어진 흐름을
설명한다.

### 4.5 현재 동결 기준선

현재 lane을 다음과 같이 명시한다.

- Hard: 2,218
- Standard: 806
- Priority: 31

Hard는 자동 경보 기준선, Standard와 Priority는 사람 검토 영역이라는
운영 의미를 함께 설명한다. 현재 결과 보고서의 Hard 성능 수치는
retrospective benchmark 결과로만 표시한다.

### 4.6 Exp403-409의 의미

Exp403-408의 각 실험 목적을 짧게 연결하고, 새 근거가 자동 경보 승격이
아니라 review-only임을 명시한다. Exp405의 demotion gate 실패와 Exp408
엄격 변형의 후보 품질을 독립적인 경고 근거로 설명한다.

Exp409는 성능 개선 실험이 아니라 label isolation, lane immutability,
budget, provenance가 작동하는지 확인한 준비성 검증으로 정의한다.
신규 데이터가 없으므로 prospective 성능의 증거가 될 수 없다는 점을
분명히 한다.

### 4.7 확정된 교훈

반복해서 관찰된 결론을 한곳에 모은다.

- 넓은 후보 확장은 대체로 TP보다 FP를 더 빠르게 늘린다.
- threshold 조정만으로 model-hard 문제를 해결하기 어렵다.
- 작은 TRAIN에서는 conformal 해상도가 제한된다.
- review 후보도 운영 비용이므로 무제한 확장할 수 없다.
- TEST 성능에 따른 family routing은 누수다.
- tail replacement는 합성 평가 배열을 이용하므로 금지한다.
- provenance와 실패 폐쇄가 성능 수치만큼 중요하다.

### 4.8 주장과 해석의 경계

다음 세 종류의 주장을 분리한다.

| 주장 종류 | 허용되는 의미 |
|---|---|
| Autonomous | 사람이 정답을 보완하지 않은 자동 경보 결과 |
| Retrospective | 현재 동결 TEST에서 사후 평가한 연구 결과 |
| Human-assisted | review 후보의 실제 정답을 사람이 완벽히 판별한다고 가정한 상한 또는 보조 지표 |

`mean_combined_f1`은 human-assisted 지표로만 다루며 autonomous 성능으로
표현하지 않는다. 현재 데이터 결과를 prospective 또는 현장 배포 성능으로
부르지 않는다.

### 4.9 이후 연구 방향

새 데이터 도착을 전제로 한 계획을 공식 기본 경로에서 제외한다. 현재
데이터만으로 가능한 후속 연구는 다음 원칙을 따른다.

- family-grouped 분할로 유사 family가 학습과 평가에 동시에 퍼지는 위험을
  줄인다.
- nested validation으로 설정 선택과 최종 평가 역할을 분리한다.
- 정상 중복 정도를 반영한 overlap-aware 결과를 함께 보고한다.
- anomaly 수와 표본 크기에 따른 불확실성을 별도로 표시한다.
- 새 개선은 새 실험 번호와 사전등록으로 분리한다.
- TEST 결과를 본 뒤 alpha, threshold, source, budget을 재선택하지 않는다.

이 방향은 “진정한 prospective 검증”을 대체한다고 주장하지 않는다.
이는 추가 데이터를 얻을 수 없는 조건에서 과장과 누수를 최소화하는
retrospective 연구 설계다.

### 4.10 문서 및 근거 지도

독자가 목적에 따라 최소 문서만 읽을 수 있도록 다음 범주로 연결한다.

- 복원과 현재 상태
- 데이터 품질과 평가 난이도
- 실험 일관성 및 역사적 결과
- Exp403-408 설계·실행·결과
- Exp409 설계·실행·준비성 결과
- 후속 실험 작성 규칙

## 5. 근거 우선순위와 충돌 처리

동일 사실에 서로 다른 설명이나 수치가 있을 때 다음 순서를 적용한다.

1. 동결된 결과 산출물 및 독립 감사 보고서
2. 해당 실험의 사전등록 문서와 실행 런북
3. handoff 및 재개 문서
4. 과거 시점의 종합 보고서
5. 초기 `README.md`

단, 사전등록 문서는 “무엇을 하기로 했는가”에 가장 강한 근거이고, 결과
보고서는 “실제로 무엇이 나왔는가”에 가장 강한 근거다. 우선순위는 문서의
역할을 무시하고 결과를 계획으로 덮어쓰라는 의미가 아니다.

충돌은 조용히 하나의 값으로 합치지 않는다. 통합 문서에서 다음 중 하나로
표시한다.

- 역사적 수치: 당시 기준에서는 유효하지만 현재 모집단과 다름
- 현재 동결 수치: 현재 운영·연구 기준
- 미확인: 원문이나 산출물을 찾을 수 없음
- 해석 변경: 새로운 감사로 과거 주장의 범위가 축소됨

## 6. 알려진 결손과 명시 방법

`docs/EXP403_408_PREREGISTRATION_KO.md`는 handoff에서 참조되지만 현재
working tree와 전체 Git 이력에서 확인되지 않았다. 통합 문서는 이를
복원하거나 존재하는 문서처럼 인용하지 않는다. 다음과 같이 기록한다.

> Exp403-408 preregistration 문서는 handoff에서 참조되지만 현재 저장소와
> 확인 가능한 Git 이력에는 없다. 설계 명세, runbook, 결과 보고서로 확인
> 가능한 범위만 사용한다.

Exp409의 기존 문서에 포함된 “향후 genuinely new data” 전제는 당시 준비성
설계의 역사적 가정으로 보존한다. 현재는 신규 실데이터가 영구적으로 없다는
사용자 확정 조건 때문에 그 경로를 실행 가능한 연구 계획으로 취급하지
않는다.

초기 `README.md`의 947개 데이터셋 및 VAE 중심 서술도 삭제하지 않는다.
통합 문서에서 현재 1,117개 동결 모집단 이전의 역사적 단계라고 설명한다.

## 7. 표현 및 인용 원칙

- 한국어를 기본으로 하고 모델명·파일명·지표명만 원문 표기를 유지한다.
- 연구자가 아닌 독자도 이해하도록 전문용어를 처음 사용할 때 짧게 풀이한다.
- 중요한 수치에는 직접 근거가 되는 저장소 문서 또는 외부 동결 산출물
  경로를 붙인다.
- 재계산하지 않은 수치를 새 분석 결과처럼 표현하지 않는다.
- retrospective 결과와 운영 정책을 같은 표에서 혼합하지 않는다.
- “SOTA”, “검증 완료”, “배포 가능” 같은 표현은 그 주장에 필요한 근거가
  없으면 사용하지 않는다.
- 외부 절대 경로는 현재 Mac에서만 유효할 수 있음을 표시하고, 저장소 내부
  문서를 우선 연결한다.

## 8. 완료 기준

통합 문서 구현은 다음 조건을 모두 충족할 때 완료된다.

1. 승인된 열 개의 본문 섹션이 모두 존재한다.
2. 현재 데이터와 반도체 현장 데이터의 관계가 오해 없이 설명된다.
3. 신규 실데이터가 없다는 전제가 후속 방향에 일관되게 반영된다.
4. Hard 2,218 / Standard 806 / Priority 31이 원 근거와 일치한다.
5. Exp408 새 근거가 review-only로 표현된다.
6. Exp409가 성능 검증으로 과장되지 않는다.
7. human-assisted와 autonomous 지표가 분리된다.
8. 누락된 Exp403-408 preregistration 문서가 명시된다.
9. 금지 원칙과 후속 실험 규칙이 빠짐없이 포함된다.
10. 코드, 실험 설정, 기존 동결 결과에는 변경이 없다.

## 9. 구현 산출물

승인 후 구현 단계에서 만드는 필수 산출물은 하나다.

- `docs/PROJECT_RESEARCH_CONTEXT_KO.md`

`README.md`에 통합 문서 링크를 추가하는 작업은 이 설계의 필수 범위가
아니다. 필요하면 별도의 명시적 승인 후 수행한다.
