Exp468 NumPy fallback 승인 설계 보완

승인 결론: 사용자는 2026-08-24에 Exp468이 NumPy CPU를 사용해 Task 4로 진행하는 예외를 승인했다. 이 승인은 가속 gate 실패를 합격으로 바꾸지 않는다. 세 사실은 각각 gate_passed=false, fallback_authorized=true, selected_backend=numpy로 따로 기록한다.

승인 근거

기존 근거는 scratch/exp468_acceleration_benchmark_antigravity.json이다. 승인 직전 이 파일의 전체 바이트 SHA-256은 938d83b0319346270a6cc32b7b6ba3efb88122dc1bf431863d8030f4539fb63b다. 이번 보완은 이 benchmark를 다시 실행하거나 수치를 고치지 않고, 이미 검증된 결과에 운영 승인을 연결한다.

확인 항목기존 기록승인 뒤 해석
NumPy 전체 workload median0.03191525023430586s선택한 CPU 경로
Numba cold-inclusive gate 시간0.5741005414165556s고정 1.1x gate 실패

바뀌는 것과 바뀌지 않는 것

바뀌는 것은 운영 선택 하나다. 실패한 가속 평가를 그대로 둔 채, 승인 SHA-256을 가진 불변 decision만 NumPy fallback을 Task 4 입력으로 확정할 수 있다. 승인이 없으면 실패 assessment를 Task 4용으로 확정할 수 없다.

  • ECG200 TRAIN-only 입력, 정상 69행, 96→140 보간과 TEST 비접근 경계를 바꾸지 않는다.
  • seed (20260721, 20261721), 5 fold, 10-fold workload와 fit/query/frame 개수를 바꾸지 않는다.
  • 5×28 창, 대칭 Hann, RFFT, DC 제외·Nyquist 포함, epsilon 1e-12, 자연로그 JS, LOO와 query full-fit reference를 바꾸지 않는다.
  • raw 허용오차 1e-12, exact rank·confirmation·determinism과 가속 기준 1.1x를 바꾸지 않는다.
  • C0/S10/C10 조립, AUC, qualification 기준, 공식·private 실행 결과를 만들지 않는다. 이 작업 뒤 다음 단계는 Task 4 구현과 성능 평가다.

감사 가능한 선택 계약

가속 gate가 실제로 통과한 경우에만 non-NumPy backend의 eligible, parity_passed, deterministic, speedup>=1.1을 모두 요구한다. gate가 실패한 경우에는 모든 non-NumPy 후보의 비어 있지 않은 실패 이유와 이 승인 문서의 64자리 lowercase SHA-256이 있어야만 fallback_authorized=true가 된다.

따라서 Task 3 완료는 “가속 성공”이 아니라 “가속 실패 사실을 보존한 승인 예외의 감사 연결 완료”를 뜻한다. private/official qualification은 여전히 0/0회이며 result와 result hash는 null이다.
