Exp454 Exp449 authority 타입 경계 복구 설계

한 줄 목표: 실제 Exp449 authority를 Exp454 내부 타입으로 한 번만 변환해, 과학 계산을 바꾸지 않고 공식 평가가 label 단계까지 도달하게 한다.

1. 왜 새 실험이 필요한가

Exp453 readiness는 고정 Python 환경에서 성공했다. 하지만 evaluate는 label을 열기 전에 ValueError: Exp448 target identity differs로 끝났다. 실제 Exp449 객체와 Exp453가 복사해 만든 클래스는 이름과 값이 같아도 Python에서 서로 다른 타입이다. Exp453가 type(...) is로 비교했기 때문에 실패했다.

Exp453는 readiness 1회, evaluate 1회, inspect 0회로 영구 종료됐다. 재실행하지 않는다. Exp454는 이 한 가지 타입 경계만 고친다.

2. 선택한 방법

단일 변환 경계를 사용한다. Exp449에서 실제 target authority를 읽은 직후, baseline과 confusion 값을 Exp454의 immutable dataclass로 한 번 변환한다. 평가기 안쪽에서는 기존 Exp453 계산 코드를 그대로 사용한다.

방법판단이유
단일 변환 경계채택변경 위치가 한 곳이고 기존 계산·검사를 유지한다.
필드만 맞으면 허용제외어떤 클래스든 통과할 수 있어 입력 범위가 넓어진다.
평가기 전체가 Exp449 타입 사용제외Exp454 계산 코드가 Exp449 구현에 강하게 묶인다.

4. 입력과 변환 흐름

  1. Exp453의 stopped receipt와 failure audit를 읽어 readiness 성공·evaluate 실패·label 0·root 없음·no-retry 사실을 확인한다.
  2. Exp449 frozen prediction authority 96개와 aggregate SHA-256 a6054a44fc4e78f354dcf61d2e003284804680cd4197405364fcb5ef8d822e0d를 그대로 확인한다.
  3. Exp449의 실제 capture_exp448_authority_antigravity() 결과를 받는다.
  4. normalize_exp449_target_authority_antigravity(authority)가 데이터셋 이름, family, stable candidates, confusion 숫자를 순서대로 Exp454 타입으로 복사한다.
  5. 변환 전후의 canonical 값·순서·48개 inventory가 정확히 같을 때만 local authority를 반환한다.
  6. 평가기는 local authority를 받아 기존 prediction matching, label query, confusion, bootstrap, decision, 12-leaf publication을 그대로 실행한다.

6. 절대 바꾸지 않는 과학 값

  • 48 datasets, 96 predictions, 16 family-method pairs
  • seeds [20260721, 20261721], alpha 0.005
  • dataset·family·method·prediction index 순서와 sorted(indices)
  • baseline confusion, candidate confusion, FN, FP, F1 계산
  • bootstrap seed·draw bytes·percentile·decision gate
  • 12-leaf 파일 이름, 순서, canonical JSON/JSONL 형식
  • routing은 연구 가능성만 표시하며 자동 routing·promotion은 계속 금지
  • 고정 runtime: Python 3.14.6, NumPy 2.3.5, aeon 1.4.0, scikit-learn 1.7.2

7. 가장 중요한 테스트

실제 authority 회귀 테스트: test-only 변환 fixture를 만들지 않고 실제 Exp449 capture_exp448_authority_antigravity() 결과를 production normalization 함수에 넣는다. 변환된 48 baseline과 global confusion이 기존 합성 fixture와 canonical하게 같고, 평가기가 label opener 직전까지 통과하는지 확인한다.

추가로 다음을 검사한다.

  • baseline 한 숫자, family, 데이터셋 순서, stable candidate가 바뀌면 변환 단계에서 실패한다.
  • 변환 함수가 두 곳 이상 생기거나 평가 중간에 다시 변환하지 않는다.
  • 동일 synthetic labels에서 Exp453의 정상화된 순수 계산과 Exp454의 12-leaf payload가 identity/hash 필드 외에는 같다.
  • unit/regression test는 실제 TEST label을 읽지 않는다.

8. 실패 처리와 공식 실행

구현 또는 합성 검증이 실패하면 공식 명령을 실행하지 않는다. 구현·Grok 독립 검토·Codex 검증·fresh Sol 최종 검토가 모두 끝난 clean commit만 공식 후보가 된다. 공식 Exp454는 별도 사용자 승인 뒤 readiness → evaluate → 성공 시 inspect 순서로 각각 한 번만 실행한다.
