Exp481 엄격 근거 잔여 보정 설계

승인된 방향: 현재 최선인 row-KNN의 결정을 기본값으로 보존합니다. row-KNN이 MiniRocket으로 돌아간 잔여군에서만, 동률을 제외한 엄격한 ZF 개선과 AUC 안전성이 모두 확인될 때 대안 방법을 선택합니다.

1. 왜 이 실험을 하는가

Exp480은 1,117개 데이터셋과 128개 원본 family에서 대안 방법을 53번 선택했지만, MiniRocket 대비 ZF 개선 4건·악화 7건으로 순변화가 -3이었습니다. 이웃의 동률을 성공으로 계산했고, 선택 방법이 기존 proposal과 53건 모두 달랐습니다. Exp481은 family 균형을 버리는 실험이 아니라, 근거가 실제 개선을 뜻하도록 통과 규칙을 바로잡는 최소 실험입니다.

2. 범위와 비범위

이번에 고정하는 것

  • 데이터셋 1,117개, 원본 family 128개, 후보 방법 네 개의 기존 점수를 그대로 사용합니다.
  • 라우팅 입력은 정상 TRAIN 데이터에서 만든 width, n_train, spectral_entropy, skewness, kurtosis, diff_std_ratio, zero_crossing_rate만 사용합니다.
  • 데이터셋 이름과 대상 family 이름은 라우팅 입력으로 사용하지 않습니다.
  • family ID는 검증 분리와 과거 근거의 중복 투표 제거에만 사용합니다.
  • 결과를 본 뒤 k, 특징, 통과 기준을 같은 Exp481에서 바꾸지 않습니다.

이번에 하지 않는 것

  • catch22/24 특징 추가, 새로운 학습 모델, 점수 결합과 앙상블은 넣지 않습니다.
  • 공식 row-KNN 코드와 기존 Exp480 공식 결과를 수정하지 않습니다.
  • TEST 라벨이나 held-out 후보 점수로 라우팅 결정을 만들지 않습니다.
  • Exp481 결과만으로 완전히 새로운 외부 데이터 일반화가 증명되었다고 주장하지 않습니다.

4. 전체 데이터 흐름

  1. Exp480의 불변 evidence SQLite와 SHA256을 검증합니다.
  2. 바깥쪽에서 원본 family 하나를 완전히 제외합니다.
  3. 남은 family만 사용해 기존 row-KNN 결정을 다시 계산합니다.
  4. row-KNN이 대안 방법을 선택했다면 그 결정을 그대로 보존합니다.
  5. row-KNN이 MiniRocket을 선택한 경우에만 strict family 후보를 평가합니다.
  6. 안쪽 leave-family-out 결과로 후보 방법의 안전성을 확인합니다.
  7. 안쪽 안전성 gate와 대상 행의 local gate를 모두 통과한 후보만 사용합니다.
  8. 모두 실패하면 row-KNN의 MiniRocket 결정을 그대로 사용합니다.
  9. 모든 바깥 family 결과를 합쳐 사전 등록된 성능 기준을 판정합니다.

5. local strict evidence

잔여 보정 후보는 MultiRocket, Hydra, Hydra+MultiRocket 세 방법입니다. 각 후보는 대상 행과 가까운 서로 다른 31개 과거 family에서 한 행씩만 사용합니다. 기존 Exp480과 달리 동률을 개선으로 세지 않습니다.

통계정의통과 조건
ZF 승ΔZF > 0인 family 수ZF 승이 ZF 패보다 많음
ZF 패ΔZF < 0인 family 수승과 별도로 기록
ZF 동률ΔZF = 0인 family 수성공률 분자에 포함하지 않음
AUC 최악값31개 family의 최소 ΔAUC>= 0
AUC 하위값31개 family의 20% 분위 ΔAUC> 0
AUC 동률ΔAUC = 0인 family 수성공으로 계산하지 않음

복수 후보가 통과하면 ZF 승-패, AUC 최악값, AUC 하위값 순으로 고릅니다. 그래도 같으면 방법을 바꾸지 않습니다.

6. 안쪽 family 검증 gate

바깥 held family를 제외한 학습 family 안에서 다시 family 하나씩을 제외해, 같은 local strict rule의 out-of-family 결정을 만듭니다. 후보 방법은 안쪽에서 다음 조건을 모두 충족해야 바깥 대상에 사용할 수 있습니다.

  • 파생 데이터셋 수가 많은 family가 다시 지배하지 않도록, 안쪽 결과도 원본 family별로 먼저 합칩니다.
  • local strict rule이 실제 결정을 바꾼 원본 family가 20개 이상이어야 합니다.
  • 각 원본 family의 ZF 변화 합계를 승·동률·패로 나누고, 승 family 수가 패 family 수보다 많아야 합니다.
  • 안쪽 채택 사례의 실제 최소 ΔAUC가 0 이상이어야 합니다.
  • 안쪽 채택 사례의 실제 AUC 하위 20% 이득이 0보다 커야 합니다.
  • 안쪽 지원 family가 20개보다 적으면 해당 후보는 비활성화합니다.
  • 이 gate 계산과 후보 순위에 바깥 held family의 특징·점수·라벨은 들어가지 않습니다.

8. 중단 조건

다음 중 하나라도 발생하면 Exp481은 개선 실패로 보존합니다. 기준을 느슨하게 하거나 > 0을 다시 >= 0으로 바꾸지 않습니다.

  • row-KNN보다 ZF 합계 또는 family 평균 ZF가 높지 않습니다.
  • 전체 평균 또는 family 평균 AUC가 row-KNN보다 낮습니다.
  • 결정 변경으로 ΔAUC <= -0.05인 사례가 한 건이라도 생깁니다.
  • 엄격 gate에서 실제 결정 변경이 0건입니다. 이 경우 현재 일곱 특징 공간을 종료합니다.
  • 안쪽에서는 통과했지만 바깥 family에서 성능이 무너지면 같은 특징과 k로 재시도하지 않습니다.

9. 결과 해석 경계

Exp481 규칙은 Exp480 결과를 보고 만든 사후 개선안입니다. 따라서 같은 1,117개에서 얻는 결과는 개발 및 재현 근거이며, 완전히 독립된 최종 일반화 증거는 아닙니다. Exp481이 모든 기준을 통과하더라도 공식 교체 전에 규칙 동결 뒤 새로운 원본 family 또는 아직 결과를 보지 않은 외부 데이터셋에서 한 번 더 검증해야 합니다.

10. 계산 가속

  • 성능에 중요한 NumPy 경로를 Numba로 바꿀 수 있는지는 항상 평가합니다. Task 2는 단순한 기준 CPU 경로를 제공하고, Task 4가 선택합니다.
  • 결정적 smoke가 유한 출력, 동일한 결정과 후보 인덱스, 사전 등록된 수치 일치, 컴파일 준비와 데이터 변환을 포함한 전체 stage 시간 단축을 모두 확인할 때만 Numba를 사용합니다.
  • 조건을 하나라도 만족하지 못하면 더 단순한 NumPy 또는 공식 서드파티 구현을 유지하고, backend·시간·parity·대체 이유를 manifest에 기록합니다.
  • 같은 입력과 seed에서 기준 경로와 후보 경로의 후보 인덱스와 최종 결정이 모두 같아야 합니다.
  • Numba 컴파일 준비 시간과 데이터 변환을 포함한 전체 중첩 평가 시간을 manifest에 기록합니다.
  • MLX는 정확한 연산 parity, 정확한 후보 인덱스, 유한 출력, 수치 허용오차, 전송·동기화를 포함한 1.1배 속도 향상을 모두 만족할 때만 사용합니다. Exp480의 float64 제한을 그대로 가정하지 않고 새 stage를 다시 측정합니다.

12. 테스트 계약

  • 동률이 strict 개선 수에 포함되지 않는 단위 테스트
  • row-KNN 대안 결정이 정확히 보존되는 테스트
  • row-KNN Mini fallback 행만 residual correction 대상이 되는 테스트
  • 안쪽과 바깥 family가 겹치지 않는 테스트
  • held-out 점수는 결정 뒤에만 읽히는 leakage 테스트
  • AUC 최악값 또는 하위값 실패 시 정확히 row-KNN으로 돌아가는 테스트
  • 작은 고정 입력에서 NumPy 기준 계산과 Numba의 후보 인덱스·결정 parity 테스트
  • 같은 입력 반복 실행의 결과 JSON bytes 일치 테스트
  • 1,117개·128 family·네 방법 완전성 및 SHA 검증
