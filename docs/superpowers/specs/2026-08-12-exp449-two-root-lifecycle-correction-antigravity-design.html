Exp449 two-root lifecycle receipt correction

Design status: approved prospective correction. It supersedes unsafe single-root and map-only-child portions of original Tasks 7–8. It changes no product code, invokes no command, opens no label session, accesses no dashboard, and authorizes no official lifecycle.

Decision

The lifecycle uses three independent namespaces: immutable prediction authority, final/forensic evaluation publication, and a receipt directory that makes every phase transition durable and non-repeatable. Predict owns only the prediction root; evaluate reads that root by descriptor and owns only the evaluation root; inspect reads both. The receipt namespace is the sole lifecycle state machine. A fixed create-only audit records failures but cannot authorize recovery.

Receipt state machine

The receipt directory is an absent-at-entry directory of canonical JSON, create-only, single-link regular leaves. The directory and every leaf are descriptor-pinned and opened no-follow; all writes fsync the leaf then the directory and revalidate the name, inode identity, link count, type, canonical bytes, inventory, and predecessor descriptor before return. No receipt contains a timestamp, random value, PID, or any nondeterministic field.

Every successful leaf has exactly these JSON fields: schema, experiment_id, run_identity, reviewed_commit, phase, event, ordinal, previous_leaf_sha256, prediction_root_identity, evaluation_root_identity, and permanent_stop. previous_leaf_sha256 is null only for ordinal 1. Root identity is null when that root cannot yet exist; otherwise it is the canonical descriptor identity. permanent_stop is exactly false on success leaves.

stopped_antigravity.json is the only failure leaf. It has the same fields with event="stopped" and permanent_stop=true, binds the primary failure phase and the exact predecessor hash, and is terminal. It is mutually exclusive with every future success leaf. Every later phase requires the exact predecessor inventory and rejects missing, reordered, surplus, foreign, replaced, symlinked, noncanonical, multi-link, partial, stopped, or receipt-write-failed state. Crash or receipt-write failure therefore leaves a permanently blocking partial/invalid nonempty namespace. A preexisting or foreign receipt namespace remains byte-identical and fails closed.

Lifecycle and failures

  1. Readiness: clean reviewed HEAD first; require prediction root, evaluation root, audit, and receipt directory absent and non-symlink; use standard library before external capture; probe isolated package/method/MLX facts; recheck clean HEAD, map fingerprints, and all four absent paths last; only then create and validate receipt directory plus readiness-complete. Direct predict requires that sole leaf; repeat readiness sees the directory and rejects.
  2. Predict: require readiness-complete only, append predict-started before work, create only the prediction root, preserve zero label access, exact 96 candidates, PCG64(44920260812), 20,000 × 48 draws, SHA-256 264c780d7e5949994f1de3053158ea20a7cc3d0ae858f29770d9849b18ad4d6a, 12 logical CPUs, 11 workers, and n_jobs=1; append predict-complete only after immutable descriptor validation.
  3. Evaluate: require prediction-complete only; capture immutable prediction descriptor before append/start and before labels; require evaluation root absent/non-symlink; append evaluate-started, open exactly one 48-query/72,300-row label session, preserve prediction bytes, create exactly 12 evaluation leaves, then append evaluate-complete.
  4. Inspect: require evaluation-complete only; append inspect-started, capture both completed root descriptors, and replay without SQLite, source, evaluator, aeon, network, dashboard, or label capability; append inspect-complete only after replay equality.

Any primary phase error attempts the stopped receipt first and then the best-effort audit. The audit schema is canonical JSON with phase, root_destinations, recovery_state, primary_error, cleanup_notes, and permanent_stop; root_destinations is exactly a JSON list: empty for readiness, otherwise ordered prediction/evaluation path strings. The public wrappers retire/bypass incompatible inner audit writers and call this unified writer exactly once. Stopped/audit write errors are secondary evidence and never mask the primary error. Occupied/symlink paths are preserved byte-for-byte; the system must never claim they became absent. If receipts are safely absent, such a readiness failure may create stopped; an existing audit or receipt never changes.

Map same-commit governance

Every governance, source/tests, readiness/CLI, and truth/report/ledgers boundary commit includes its synchronized Exp449 map HTML, JSON, and lock in the same commit. The old map-only-child pattern is historical only. The map lock has schema="exp449_codemap_same_commit_v1", source_parent_commit, working_tree_dirty=false, represented_paths, and deterministic module fingerprints of the proposed post-change tracked tree excluding only the map triplet. At generation, false means no changed path is unrepresented; after commit it also requires a clean tree. Readiness at reviewed HEAD verifies that lock source-parent equals HEAD’s first parent and that current tracked fingerprints equal the lock. This removes self-reference without modifying AGENTS.md.
