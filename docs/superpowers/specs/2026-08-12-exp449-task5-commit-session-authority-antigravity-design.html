Exp449 Task 5 CommitSession Authority 보완 설계

작성일: 2026-08-12 · 범위: Exp449 Task 5 전용 · 문서 형식: self-contained HTML

상태: 구현 승인됨. 이 문서는 기존 Exp449 계획의 Task 5를 보완하며 Task 6을 승인하지 않는다. Task 5 체크박스는 구현, 검증, fresh Sol ship 전까지 미완료로 유지한다.

1. 문제와 근본 원인

  • 기존 CandidateCommitReceiptAntigravity는 공개 구조 데이터라 호출자가 파일을 stat/hash한 뒤 동일한 객체를 만들 수 있다.
  • 기존 progress API는 root, inventory, receipts, completed count를 호출자에게 받아 writer가 실제로 성공 반환했다는 이력을 증명하지 못한다.
  • 운영 실패 catch의 receipt 재검증이 audit 보호 경계 밖에서 예외를 발생시키면 원래 실행 오류와 audit가 사라질 수 있다.

2. 선택한 구조

Task 5 lifecycle 내부에서만 생성되는 module-private slotted CommitSessionAntigravity가 candidate commit, 성공 이력, progress, prefix 검증을 단일 소유한다. 세션은 lifecycle 밖으로 반환되지 않고 외부 상태에서 복원되지 않는다.

2.1 세션 생성

  • module-private factory만 root와 exact 96-name inventory로 빈 세션을 만든다.
  • receipt 생성자, receipt 반환 옵션, caller-supplied receipt/count 기반 공개 API를 제거한다.
  • Python 이름 은닉 자체를 보안 경계로 주장하지 않는다. 권한은 세션 내부에서 durable writer 성공 후에만 append되는 provenance다.

2.2 commit

session.commit(sequence, value)
  • sequence == internal_commit_count 및 inventory[sequence]를 강제한다.
  • 기존 O_EXCL, leaf/parent fsync, canonical no-follow reread, fd-derived inode/SHA 검증을 그대로 수행한다.
  • writer가 성공 반환한 뒤에만 세션 내부 state를 append한다. duplicate, skip, out-of-order, name adoption은 거부한다.

2.3 progress

session.record_progress()
  • 호출자가 completed count를 넘기지 않는다.
  • 세션 내부 성공 수에서만 progress JSON/JSONL/text를 계산한다.
  • 동일 count 중복 기록, count skip, 내부 state와 불일치한 progress를 거부한다.

2.4 prefix 검증

session.validate_prefix() -> PrefixValidationAntigravity
  • 세션 내부에 기록된 성공 commit만 descriptor/no-follow 방식으로 순서대로 재검증한다.
  • unreturned namespace leaf는 canonical/official-shaped여도 절대 세지 않는다.
  • 성공 commit k가 missing, replaced, symlinked, unreadable, noncanonical, inode/SHA mismatch면 valid_prefix=k와 별도 prefix_validation_error를 반환한다.
  • 검증 결과 객체는 예외를 통해 lifecycle primary error를 덮지 않는다.

3. 실패 및 audit 계약

  • synthetic과 production은 동일한 session 실패 경로를 사용한다.
  • catch는 원래 primary exception을 보존하고 마지막에 bare raise한다.
  • prefix validation과 sibling audit persistence를 각각 독립 보호한다.
  • audit는 exact_next_sequence=valid_prefix, 별도 prefix_validation_error, primary/cleanup/PID/audit 오류를 canonical schema로 구분한다.
  • audit write 실패도 primary를 교체하지 않고 별도 note로 남긴다.

4. 유지되는 불변 조건

  • exact 96 ordered units, ProcessPoolExecutor(max_workers=11), parent contiguous commit.
  • canonical 13-field candidate payload와 frozen family/method/seed/alpha/scoring semantics.
  • terminal manifest 이전/이후 descriptor semantic validation과 manifest exact-inode cleanup.
  • 공식 root/audit 부재, TEST label 접근 0, DB 불변, dashboard/site/network 미접근.
  • Task 6 미시작.

5. TDD 및 승인 기준

  1. 공개 receipt constructor/return option/raw progress APIs가 더 이상 존재하지 않는 RED/GREEN.
  2. duplicate/out-of-order/skipped commit 및 caller-supplied completed state 거부.
  3. 0/47/95의 official-shaped unreturned leaf가 prefix/audit를 전진시키지 않음.
  4. 기존 성공 leaf의 missing/replacement가 정확한 longest prefix와 validation error를 반환.
  5. prefix validator와 audit writer 동시 실패에서도 동일 primary exception/traceback 보존.
  6. production과 synthetic catch가 동일 세션 경계를 사용함을 실경로 테스트.
  7. 96-unit/11-worker 성공 artifact bytes 및 terminal validator 불변.
  8. Task 5 전체 2회, 영향 회귀, compile, map validator, 외부 불변성 통과 후 fresh Sol ship.

6. 제외 범위

런타임 HMAC receipt, durable receipt journal, resume/recovery, Task 6 평가, 공식 실행, dashboard publication은 이 보완 설계에 포함하지 않는다.
