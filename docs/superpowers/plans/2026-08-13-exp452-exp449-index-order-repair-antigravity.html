Exp452 Exp449 인덱스 순서 복구 구현 계획

Agent 실행 규칙: Task별로 superpowers:subagent-driven-development를 사용한다. 각 Task는 Terra 구현, 테스트, 코드맵 동기화, fresh review까지 끝나야 다음 Task로 넘어간다. 완료된 Task와 Step만 체크한다.

목표: Exp449의 과학 계산은 그대로 두고 evaluation evidence의 index를 항상 정렬해 source-free replay가 통과하도록 만든다.

구조: Exp452는 Exp449의 필요한 평가 경계만 통제된 복사본으로 만든다. Exp449 prediction과 실패 evidence는 읽기 전용이다. 의미 있는 변경은 list(frozenset) 대신 sorted(frozenset)을 쓰는 한 곳뿐이다.

기술: Python 3.14, stdlib, NumPy, SQLite read-only label session, canonical JSON/JSONL, descriptor-pinned validation, unittest.

Global Constraints

  • 승인 설계 commit은 b9ff4bf6b76e37f00146f3080edb9c58068d43ee, SHA-256은 59396a3619a9878e402bcdb2bb7598438ba44d28c125537c8f1902194d049075이다.
  • Exp449 prediction aggregate a6054a44fc4e78f354dcf61d2e003284804680cd4197405364fcb5ef8d822e0d와 Exp449 artifacts는 수정하지 않는다.
  • 96개 후보 중 75개는 list 순서만 다르고, 75개 모두 index 집합은 같다.
  • Exp449 qualified candidate 2개를 선택, threshold, routing, 후보 제거에 사용하지 않는다.
  • 48 datasets, 96 predictions, 16 family-method pairs, seeds, alpha, bootstrap, FN·FP·F1 기준을 바꾸지 않는다.
  • 사람이 읽는 새 문서는 self-contained HTML이다. 모든 새 파일명에 antigravity를 넣고 Markdown 복사본과 __init__.py를 만들지 않는다.
  • Exp452는 CPU 단일 프로세스를 사용한다. Readiness는 PyTorch/MLX/mlx-metal/MPS 상태와 tensor 부적합 이유를 기록한다.
  • 공식 명령은 readiness, evaluate, inspect뿐이며 각각 한 번이다. 실패하면 영구 중단하고 재시도하지 않는다.
