Exp460 ECG 엄격 복귀 규칙 구현 계획

작업자 지침: Task별로 진행하며 각 Task 종료 후 검토한다. 구현 시 superpowers:subagent-driven-development 또는 superpowers:executing-plans를 사용한다. 체크박스는 실제 완료된 항목만 체크한다.

목표: Exp459의 고정된 10개 구간 결과를 이용해 10/10 엄격 복귀 규칙을 평가하고, 안정성과 FN 개선을 동시에 만족하는지 HTML 대시보드에 보여준다.

구조: Exp459 공식 결과를 읽기 전용 과학 입력으로 고정하고, 네 규칙의 route와 혼동행렬을 다시 계산한다. 새 모델이나 새 점수를 만들지 않으며, 결과 저장과 재검사도 이 고정 입력에서 다시 계산한다.

기술: Python 3.14.6, NumPy 2.3.5, 표준 unittest, canonical JSON/JSONL, 정적 HTML.

설계서: docs/superpowers/specs/2026-08-20-exp460-ecg-strict-fallback-antigravity-design.html

전체 고정 조건

  • 실험 ID는 Exp460, 종류는 ecg_strict_fallback이다.
  • 대상은 ECG5000_normal_2 하나다.
  • 규칙 이름과 순서는 always_baseline, always_candidate, majority_8_of_10, strict_10_of_10이다.
  • 공식 선택 대상은 strict_10_of_10 하나다.
  • 10개 중 하나라도 실패하면 엄격 규칙은 baseline이다.
  • Exp459의 seeds, folds, AUC, threshold, 혼동행렬과 공식 hash는 바꾸지 않는다.
  • 새 TRAIN 계산, 새 seed, 새 임계값, TEST 라벨 접근은 금지한다.
  • 공식 Task 6은 구현·비공식 재현·최종 검토 후 사용자의 별도 승인을 받아 한 번만 실행한다.
  • 새 파일 이름은 모두 antigravity를 포함한다.

완료 판단

Exp460의 가장 중요한 결과는 “엄격 복귀가 불안정한 후보를 막았는가?”와 “그 상태에서도 FN 개선이 남았는가?” 두 가지다. 예상대로 baseline으로 돌아가 FN이 837이 되면 규칙은 안전하게 작동했지만 성능 목표는 달성하지 못한 것이다. 이 경우 다음 실험은 임계값을 느슨하게 바꾸는 것이 아니라 period_change에 강한 새 특징을 검증한다.
