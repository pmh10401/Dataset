# Exp422-TEST-EVAL Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Exp422의 운영·MPS 수치 진단과 분리된 사후 평가 단계에서, 사전에 동결된 예측 좌표와 TEST 정답을 대조하여 포인트 단위 혼동행렬을 계산한다. 예측 산출물이 없으면 라벨을 열지 않고 명시적으로 `blocked_no_prediction`으로 종료한다.

**Architecture:** 동결 예측 검증 → 라벨 스냅샷 검증 → 순수 혼동행렬 계산 → 결정론적 보고서/매니페스트 작성의 네 계층으로 나눈다. Exp422-IR/IR-E의 MPS 진단 매니페스트는 성능 예측으로 오인하지 않으며, 새로운 평가 결과로 alpha·threshold·source·budget·lane을 재선택하지 않는다.

**Tech Stack:** Python 3.14, standard-library `csv`/`json`/`hashlib`/`sqlite3`, frozen dataclasses, `unittest`, canonical JSON/SHA256

## Global Constraints

- Exp422-IR/IR-E는 TRAIN-only 수치 진단이며 혼동행렬 입력으로 사용할 수 없다.
- 평가 입력은 동결된 prediction JSONL과 그 매니페스트이다. prediction에는 TEST 라벨·실제 이상 위치·평가 지표가 없어야 한다.
- TEST 라벨은 prediction SHA256·매니페스트 SHA256·DB SHA256·좌표 범위를 검증한 뒤에만 연다.
- TEST 결과는 연구용 사후 측정이며 운영 정책, 모델, alpha, threshold, source, budget, lane을 변경하지 않는다.
- 예측 파일이 없거나 전체 TEST 모집단을 덮지 못하면 혼동행렬을 계산하지 않고 `blocked_no_prediction` 또는 `blocked_incomplete_prediction`을 기록한다.
- 기존 Exp416 산출물은 참고 기준으로만 남기며 Exp422 결과로 복사하거나 재명명하지 않는다.
- 출력은 새 디렉터리에만 작성하고 기존 산출물을 덮어쓰지 않는다.
