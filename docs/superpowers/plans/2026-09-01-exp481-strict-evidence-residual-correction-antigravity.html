Exp481 엄격 근거 잔여 보정 구현 계획

Agentic workers: 구현 시 superpowers:subagent-driven-development 또는 superpowers:executing-plans를 사용합니다. 각 단계는 실제 완료와 검증 직후에만 체크합니다.

목표: 현재 최선인 row-KNN 결정을 보존하면서, row-KNN이 MiniRocket으로 돌아간 사례 중 근거가 엄격하게 확인된 일부만 다른 방법으로 바꿔 ZF를 2,111보다 높입니다.

구조: Exp480의 검증된 1,117행 evidence DB를 읽기 전용으로 재사용합니다. 바깥쪽 leave-one-family-out은 최종 일반화를 측정하고, 그 안의 leave-one-family-out은 후보 방법이 안전한지 학습 구간에서만 확인합니다. 실제 라우팅은 이름이 아닌 고정된 TRAIN 특징 7개만 사용합니다.

기술: Python 3.14, NumPy 2.3.5 기준 CPU 경로, 선택적 Numba 0.63.1(parity와 전체 stage 속도 이득이 확인된 뒤에만), pytest, SQLite 읽기 전용, 선택적 MLX/MLX-Metal, 정적 HTML.

설계서: Exp481 승인 설계서

전체 제약

  • 공식 기본값은 Exp480에서 검증된 row-KNN입니다. row-KNN이 대안을 골랐다면 Exp481은 그 결정을 그대로 보존합니다.
  • 잔여 보정 대상은 row-KNN이 minirocket_local_gap을 고른 행뿐입니다.
  • 라우팅 입력은 width, n_train, spectral_entropy, skewness, kurtosis, diff_std_ratio, zero_crossing_rate뿐입니다.
  • 데이터셋 이름과 family 이름은 split, family당 한 표 처리, 결과 집계에만 사용하고 라우팅 특징에는 넣지 않습니다.
  • 가까운 31개 서로 다른 family에서 ZF 개선 수가 악화 수보다 많고, AUC 최악값이 0 이상이며 AUC 하위 20% 값이 0보다 큰 후보만 local gate를 통과합니다. ZF 동률은 개선 수에 넣지 않습니다.
  • 안쪽 gate는 실제로 결정이 바뀐 family가 20개 이상이고, ZF 개선 family 수가 악화 family 수보다 많으며, 채택 사례 AUC 최악값이 0 이상이고 하위 20%가 0보다 클 때만 후보를 활성화합니다.
  • 성능에 중요한 NumPy 경로는 항상 Numba 대체 여부를 평가합니다. 결정적 smoke가 유한 출력, 동일한 결정과 후보 인덱스, 사전 등록 수치 일치, 컴파일 준비와 데이터 변환을 포함한 전체 stage 시간 단축을 확인한 뒤에만 Numba를 선택합니다. 그렇지 않으면 더 단순한 NumPy 또는 공식 서드파티 구현을 유지하고 backend·시간·parity·대체 이유를 기록합니다.
  • MLX는 정확한 연산 parity, 정확한 후보 인덱스, 유한 출력, 수치 허용오차, 전송·동기화 포함 1.1배 속도 향상을 모두 만족할 때만 해당 거리 stage에 사용합니다.
  • 원본 DB, Exp480 evidence DB, Exp480 결과와 공식 row-KNN은 수정하지 않습니다.
  • Task 6 공식 1,117개 실행은 별도 사용자 승인 전에는 실행하지 않습니다.
  • 모든 새 파일 이름에는 antigravity를 포함합니다.

def strict_statistics_reference_antigravity(zf_gains, auc_gains, q):
    zf = tuple(int(value) for value in zf_gains)
    auc = tuple(float(value) for value in auc_gains)
    wins = sum(value > 0 for value in zf)
    losses = sum(value < 0 for value in zf)
    ties = len(zf) - wins - losses
    minimum = min(auc)
    q20 = float(np.quantile(np.asarray(auc, dtype=np.float64), q))
    return ReferenceStatisticsAntigravity(
        passed=wins > losses and minimum >= 0.0 and q20 > 0.0,
        zf_wins=wins, zf_losses=losses, zf_ties=ties,
        min_auc_gain=minimum, q20_auc_gain=q20,
    )

def _unique_best_antigravity(assessments):
    passed = tuple(item for item in assessments if item.passed)
    if not passed:
        return None, "strict_local_gate_failed"
    ranks = tuple((item.zf_wins - item.zf_losses,
                   item.min_auc_gain, item.q20_auc_gain) for item in passed)
    best_rank = max(ranks)
    winners = tuple(item for item, rank in zip(passed, ranks, strict=True)
                    if rank == best_rank)
    return (winners[0], "strict_candidate_accept") if len(winners) == 1 else (None, "candidate_rank_tie")

def aggregate_inner_gate_antigravity(method, selected_records):
    by_family = defaultdict(list)
    for record in selected_records:
        if record.method == method and record.changed:
            by_family[record.held_family].append(record)
    family_zf = {family: sum(item.zf_gain for item in items)
                 for family, items in by_family.items()}
    auc = tuple(item.auc_gain for items in by_family.values() for item in items)
    minimum = min(auc) if auc else float("-inf")
    q20 = float(np.quantile(np.asarray(auc), 0.20)) if auc else float("-inf")
    wins = sum(value > 0 for value in family_zf.values())
    losses = sum(value < 0 for value in family_zf.values())
    ties = len(family_zf) - wins - losses
    enabled = len(by_family) >= 20 and wins > losses and minimum >= 0.0 and q20 > 0.0
    return InnerCandidateGateAntigravity(
        method=method, enabled=enabled, changed_families=len(by_family),
        winning_families=wins, losing_families=losses, tied_families=ties,
        min_auc_gain=minimum, q20_auc_gain=q20,
    )
