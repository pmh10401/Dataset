확인한 지식과 남은 질문

GitHub 문서 게시본: 2026-09-29 연구 작업트리의 기록이다. 최신 서비스 코드 전체의 배포본이 아니며, 미게시 자료와 원본/게시 사본의 구분은 출처 목록에 있다.

‘관측 사실’, ‘현재 판단’, ‘미검증 가설’을 구분한다. 아래 기각은 시험한 구성에 대한 것이며 기법 전체의 불가능성 증명이 아니다.

특징 추가·재학습만으로 선택기가 좋아지지 않았다

관측: 거리만 바꾼 Exp484와 catch22를 쓴 Exp488의 실제 라우팅 변경은 0이었다. Exp492의 점수 안정화 AUC 개선이 Exp493 선택기 개선으로 이어지지 않았고, Exp539 GLiClass도 학습 전후 모두 MiniRocket을 선택했다. [e484] [e488] [e492] [e493] [e539]

판단: 학습 완료, 손실 감소, 모델 크기 증가를 탐지 개선으로 세지 않는다. 새 선택기는 동일 입력 정보를 쓰는 수치 대조군과 고정 전문가 기준선을 함께 넘어야 한다. Exp539는 약 554만 개 파라미터가 실제 갱신되고 저장 모델 재생도 일치했지만 선택이 바뀌지 않았다. [e539] [n539]

추가 탐지 수보다 교환관계가 중요하다

Exp521의 max 결합은 기준과 같은 판정이었다. 보정 OR은 예산을 나누면서 기존 탐지를 잃었고, 단순 OR은 오탐을 늘렸다. Exp525는 공통 미탐 63개를 잡아도 단독 교체 시 탐지율이 하락했다. Exp536 직접 거리 세 방법도 공통 미탐을 120~129개 포착했지만 새 미탐 656~783개를 만들었다. [e521] [e522] [e525] [e536]

판단: ‘공통 미탐 회수’는 필요하지만 충분한 조건이 아니다. 같은 행에서 TP/FP/FN/TN 및 네 종류의 증감을 모두 보고해야 한다.

원시 평균·진폭 정보는 일부 신호지만 범용 개선은 미확정이다

Exp524는 Crop의 행 정규화에서 없어지는 정보가 공통 미탐 일부에 남아 있음을 보였다. 단독 통계 점수 Exp525는 악화됐지만 파형과 같은 참조에서 거리를 합친 Exp526은 0.5%에서 +0.992%p를 보였다. 구간은 0을 포함했고 순증 54개 중 52개가 Crop이었다. [e524] [e525] [e526]

Exp527의 다섯 분할 평균 차이는 +0.224%p, 95% 구간 [−0.994,+2.245]%p였다. Crop을 제외한 계열평균은 32.647→32.023%로 낮아졌다. 현재 판단: 전체에 안정적인 개선으로 승격하지 않는다. TEST 결과를 보고 Crop만 골라 적용하는 규칙도 추가하지 않는다. [e527]

보정과 표현 문제를 분리해야 한다

Exp523의 공통 미탐 1,340개 중 190개는 사후 최선 점수에서 정상 상위 0.5% 범위, 720개는 정상 5% 초과와 겹쳤다. Exp537의 다른 서비스 집단에서는 1,717개 중 694개가 사후 상위 0.5%였다. 이 두 집단·점수원·문턱은 다르므로 하나의 개선 가능량으로 합산하지 않는다. [e523] [e537]

관측: 서비스의 OOF 보정은 약 80% TRAIN 적합, 추론은 full TRAIN 적합을 쓴다. 944/955개에서 TEST 정상 Q90이 더 낮았다. 미확정: 이를 학습량 차이의 인과 효과라고 단정할 수 없다. 데이터 분포·참조 구성·중복·작은 꼬리 표본이 함께 다르다. [e537]

Exp538에서 동일 정상 H를 두 포함 관계 FIT로 비교했지만, 주분석 MiniRocket·MultiRocket의 변화 구간은 0을 포함했다. 중복 없는 보조 204개에서는 Hydra까지 모두 0 포함이었다. 0.5% 정상 오탐 비교는 4개 데이터셋·221행뿐이어서 해결된 문제로 기록하지 않는다. [e538]

수치 안정성과 가속은 탐지 개선과 별도로 검증한다

작은 정규화 분모가 점수를 크게 증폭한 실제 사례가 있었다. Exp530은 초기 거리 계산의 고정밀 일치 실패를 보존하고 QR 기반 안정 산술을 검증했다. 수치 검산 통과가 새로운 점수원의 성능 우위를 뜻하지는 않는다. [diag489] [e492] [gate530] [e530]

Core ML 사전 probe는 빨라져도 float64 판정과 불일치했다. Exp513에서는 후보 추출 후 CPU 정밀 재계산 등 한정 경로의 일치·속도 신호가 있었다. 따라서 ‘Core ML은 항상 불가능’과 ‘Core ML은 전체에 검증 완료’ 둘 다 과장이다. 현재 공유 서비스는 공식 CPU 변환과 float64 거리를 유지한다. [coreml] [e513] [shared]

Exp539는 MPS 추론 일치와 학습 후 일치를 구별했고, 학습 오차가 허용치를 넘어 CPU를 사용했다. Ollaya 서버 실행이나 ONNX 배포를 검증한 실험이 아니다. [e539]

남은 질문 — 새 실행 승인이 아닌 기록
