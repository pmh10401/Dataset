데이터와 평가 기준

GitHub 문서 게시본: 2026-09-29 연구 작업트리의 기록이다. 최신 서비스 코드 전체의 배포본이 아니며, 미게시 자료와 원본/게시 사본의 구분은 출처 목록에 있다.

무엇을 검증하는 데이터인가

원본 카탈로그는 1,119개다. 역사 문서에 따르면 UCR의 클래스별 one-vs-all 파생 1,118개와 CornellWhaleChallenge 1개로 구성된 연구용 벤치마크다. 반도체 설비 실측 성능을 직접 증명하는 데이터가 아니다. 새 실데이터가 없다는 사용자 조건을 유지한다. [context] [class479]

한 행은 시계열 구간 하나다. 파생 라벨이 시계열 길이에 반복 저장돼 있어도 실제 고장 시점을 알려 주는 라벨로 해석하지 않는다. 같은 원자료의 클래스별 파생, 반복 정상, 작은 TRAIN/TEST, 단일 이상이 평가에 영향을 준다. 과거 중복 비율은 당시 감사 스냅샷이며 이번에 DB를 다시 센 값이 아니다. [context]

네 가지 평가를 분리한다

종류문턱/학습 자료무엇을 알 수 있는가대표 근거
사후 순위 평가·ZFTEST 정상과 라벨로 오탐 예산을 계산기존 점수의 분리·정렬 능력. 운영 문턱이나 미래 오탐 보장이 아님. ZF는 TEST 정상 최대 점수를 엄격히 넘은 이상 개수.[e494] [e502] [e512]
정상 TRAIN 합성 검증정상 TRAIN의 고정 변형과 보류 정상후보 선별·학습 신호 진단. 실제 이상 탐지율을 대신하지 않음.[e508] [e509] [e514]
별도 CAL의 고정 문턱FIT로 모델, 별도 정상 CAL로 임계값, AUDIT/TEST로 평가그 집단에서 관측된 실제 탐지율·오탐률. 표본 부족은 unavailable.[e520] [e521] [e532]
현재 서비스 OOF + p-floor5-fold 정상 OOF 점수를 모아 full-FIT 모델의 query와 비교기존 서비스 정책의 관측 결과. 같은 모델을 쓰는 독립 split-conformal과 다르고 소표본에서는 목표가 완화됨.[e537] [e539]

따라서 Exp502의 1,117개 순위 평가 56.6252%(@0.1%), Exp521의 56개 고정 문턱 33.759%(@0.5%), 서비스 955개의 40.825%(@목표 0.5%)는 전후 성능 하락 곡선이 아니다. 같은 행·같은 집단·같은 지표·같은 FIT/보정 규칙으로 짝을 맞춰야 한다. [interim] [recovery]

주지표와 해석

주지표: 데이터셋별 TP/(TP+FN)을 계열 안에서 평균한 뒤 계열에 동일 가중한 탐지율. 전체 TP/FP/FN/TN, 전체 FPR=ΣFP/Σ(FP+TN), 계열평균 FPR, 목표 초과 데이터셋 수를 함께 기록한다. 계열평균과 전체 비율은 분모가 다르다. 목표 오탐률 0.5%를 주기준, 0.1%·1%를 보조로 쓴 최근 실험과, 과거 0.1% 주기준을 구별한다.

탐지율이 낮아지면서 오탐만 줄었다면 탐지 성능 개선이라 하지 않는다. 추가 탐지만 세지 말고 새 미탐·추가 오탐·제거된 오탐을 같은 행에서 비교한다. 단순 OR은 각 방법에 같은 α를 주면 총 예산이 달라진다. [e521] [e522] [e536]

bootstrap은 프로토콜의 단위와 횟수·시드를 그대로 표시한다. Exp521~532는 주로 계열 단위 2,000회, Exp536은 세 후보에 대해 98.33% 구간, Exp539는 80개 연결 원본 그룹 단위 2,000회다. 0을 포함하는 차이는 개선 불확실이며, 반복 탐색 편향이나 재학습 변동 전체가 제거되는 것은 아니다. [e521] [e536] [e539]

이 수는 p≤α 경보를 표현할 수 있는 최소 해상도다. 교환가능성·의존성·모델 일치까지 보장하는 숫자가 아니다. 부족한 CAL의 최댓값을 문턱으로 쓰고 “0.5% 보장”이라고 부르지 않는다. Exp519의 작은 CAL에서는 Exp502의 관측 전체 FPR이 7.48%였다. [e519] [interim]

라벨 접근과 재사용 경계

원칙은 정상 TRAIN으로 특징·점수·보정·후보를 정하고, 코드·입력·행 ID·점수·임계값을 동결한 다음 TEST 라벨을 평가에만 읽는 것이다. 과거 TEST를 이미 보았다는 사실은 freeze 이후에도 사라지지 않는다. 결과로 같은 실험의 설정을 고치거나 운영 모델로 승격하지 않는다.

Exp539의 명시적 예외: 사용자 승인 아래 과거 TEST 성능을 라우터의 교차검증 학습 목표로 사용했다. 각 outer 학습 그룹의 결과만 학습에 쓰고 held-out 그룹의 라벨은 배제했다. 입력은 정상 TRAIN의 7개 특징뿐이다. 이 설계를 “TEST 라벨을 전혀 사용하지 않은 정상 전용 학습”이라고 기록하면 잘못이다. [e539]

라벨을 연 완료 실험은 재학습·재점수화를 차단하고 동결 산출물의 평가·검증만 허용한다. AUDIT를 FIT나 CAL로 편입한 뒤 다시 독립 검증 표본으로 세지 않는다. 원시 DB·TEST 라벨을 외부 검토자에게 제공하지 않는다. [e531] [e532] [e539]
