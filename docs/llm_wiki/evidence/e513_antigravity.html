Exp513: Laya와 Core ML은 어디에 도움이 되는가

18개 계열의 정상 TRAIN 자료만 사용한 적용 가능성 시험입니다. 기존 Exp502·Exp512 결과와 모델을 변경하지 않았습니다. 성능 향상, 속도 향상, 수치 보존을 분리하여 판단합니다.

확인된 이득은 실행 속도입니다. Laya 단독·결합·경보 억제는 낮은 오탐을 유지하는 탐지 개선을 보이지 않았습니다. CPU+Neural Engine 설정은 같은 Laya 전체 호출에서 CPU 전용 대비 중앙값 2.54배 빨랐습니다. Core ML 후보 추출 후 CPU 정밀 재계산은 배치 128에서 점수 단계 중앙값 1.21배와 18/18 수치 일치를 보였습니다. 별도 CPU 계산 개선은 원래 Python 3.14 환경에서 중앙값 7.31배였습니다. 원래 입력 중 8,026행은 빠른 경로로, 19행은 CPU 복귀로 일치했으며 추가 576개 경계 사례는 모두 CPU 복귀를 검증했습니다.

범위와 재현성

기존 대표 50계열 중 정상 TRAIN 96개 이상인 18계열 전부를 고정했습니다. 각 계열 32개로 원래 Exp502를 적합하고, 32개를 정상 평가용으로 떼고, 나머지를 임계값 보정용으로 사용했습니다. 분할은 seed 20260721로 고정했으며 역할 간 표본 중복이 없습니다. 여덟 합성 변형은 원래 고정 함수를 재사용했습니다. 모든 특성·통계 적합은 fit 표본에서만 수행했습니다.

특징 차원은 8,064이며 수치 비교는 rtol=1e-10, atol=1e-8, 안정 정렬 순위와 고정 임계값 판정을 함께 봅니다. 표의 통과는 이 표본에서 관찰한 일치입니다. 실제 미래 입력에 대한 수학적 보장이 아닙니다.

가속: 18계열 × 배치 3종 × 방법 5종

독립 검토 후 CPU와 후보를 바로 짝지어 5회 측정하고, CPU 선행/후행 순서를 번갈아 적용했습니다. 각 쌍의 속도 비율 중앙값을 사용하며 아래 표는 계열 중앙값입니다. 최초 방법별 실행 순서를 섞은 측정은 진단 기록으로만 남기고 속도 통과 판단에는 사용하지 않습니다. 입력 변환·Core ML 호출·출력 및 CPU 재계산을 포함합니다. 변환/로드/첫 호출은 별도 기록했으며 아래 수치는 준비 후 반복 실행입니다. 기존 FP16 비유한값은 실패로 유지하고 속도 수치를 부여하지 않았습니다.

추가로 확인한 CPU 계산 개선

첫 lowrank 구현은 PowerCons에서 거의 같은 큰 수를 뺄 때의 상쇄 오차로 점수 오차 기준을 넘었습니다. 잔차가 32 × gamma_p × (norm + projected_norm) 이하인 행만 기존 CPU로 계산하도록 보완했습니다. gamma_p = p × eps / (1 − p × eps)이며 데이터셋 이름에 따른 분기는 없습니다. 고정 reference 투영은 미리 계산하고 마지막 불완전 배치의 불필요한 채움도 제거했습니다.

실험 worktree의 Python 3.14.6 / NumPy 2.3.5 환경에서 같은 입력에 CPU와 후보를 인접하게 5회 비교했습니다. 점수 단계 중앙값 7.31배, 최소 2.06배이며 8,045행 중 19행만 기존 CPU로 돌아갔습니다. 18/18계열에서 점수 허용 오차·순위·판정이 일치했고 빠른 계산 경로의 근거는 CPU로 돌아가지 않은 8,026행입니다. 추가 경계 사례는 fitted-span 내부 288행과 작은 교란을 더한 near-span 288행이며, 576행 전부 CPU 복귀를 사용해 원본과 일치했습니다. 이는 복귀 조건과 기존 계산 경로의 검증입니다. 최종 보고 단계에서 실제 점수 계산을 다시 검증했습니다. 별도 환경의 Core ML 표와 속도 우열을 직접 비교하지 않습니다.

검증·제약

Laya 저장 점수·고정 결합 식·역할 분리·변형별 집계를 독립적으로 재계산했습니다. 점수 계산용 Core ML의 전 계열 비교는 실행 중 CPU 기준 비교와 반복 출력 검사에 근거합니다. Laya의 별도 장치 비교는 위 24개 입력으로 제한됩니다. Pro 자문은 연결 시간 초과였고 Grok의 독립 설계 검토와 별도 코드 검토 기록을 보존했습니다. 물리적인 ANE 실행 추적은 하지 않았습니다.

Laya에는 8,045개 입력을 두 표현으로 제공하여 총 16,090개 확률을 얻었습니다. 각 계열·표현의 첫 3개만 재호출해 108개 출력의 재현성을 확인했습니다. 전체 16,090개를 두 번 실행한 검사는 아닙니다. Python 3.14에서는 앞선 소스 설치/가져오기만 성공했고 Core ML 네이티브 추론은 실패했으므로 이번 Laya 실행은 별도의 Python 3.12 환경을 사용했습니다.
