연구 보고서의 정적 게시 사본입니다. 본문은 당시 결과이며 현재 배포 상태를 뜻하지 않습니다. 링크를 저장소 기준으로 바꾸고 실행 스크립트와 미게시 그림을 제외했습니다. 실시간 진행 표시·대화형 기능은 갱신되지 않습니다. 원본 경로·해시·게시 사본 정보

원시 CSV → 이상 검토 → 사용자 보고

사용자가 정상이라고 확인한 기준 CSV와 분석할 CSV를 새 로컬 DB에 등록합니다. 기존 웹 화면에서 분석을 시작하고, 각 시계열의 점수·원본 그래프·분석 기록을 확인합니다. 분석할 CSV에는 정답 라벨이 필요하지 않습니다.

1. 입력 파일 준비

두 파일 모두 UTF-8 CSV이며 헤더는 아래 순서를 따릅니다. 아래는 형식 설명용 첫 세 행입니다. 실제 파일에는 각 ID마다 최소 9개 측정값이 필요합니다.

series_id,timestamp,value
sensor-window-01,2026-09-25T09:00:00+09:00,12.3
sensor-window-01,2026-09-25T09:00:01+09:00,12.6
sensor-window-01,2026-09-25T09:00:02+09:00,12.4
  • series_id 하나가 분석 단위인 구간 하나입니다. 구간 분할은 입력 전에 정해야 합니다.
  • 정상 기준에는 최소 5개 구간이 필요합니다. 기준·분석 구간 모두 길이와 측정 간격이 같아야 합니다.
  • 시간에는 UTC 오프셋이 필요하며 ID 안에서 엄격히 증가해야 합니다. 중복 시간·불규칙 간격·결측값·무한값·상수 구간은 거부합니다.
  • 정상 기준은 사용자가 정상임을 확인한 별도 파일이어야 합니다. 프로그램이 정상 여부를 대신 보증하지 않습니다.

2. 새 DB로 가져오기

서비스 의존성이 설치된 Python 환경에서 저장소 루트를 작업 디렉터리로 사용합니다. 아래 /path/... 경로를 실제 경로로 바꾸세요. 이미 DB가 있는 디렉터리는 덮어쓰지 않습니다.

python3 -m services.time_series_anomaly_diagnosis.csv_importer \
  --normal-reference /path/normal.csv \
  --queries /path/query.csv \
  --data-dir /path/new-analysis \
  --name "설비 A 측정 구간"

원본 파일은 변경하지 않습니다. 원본 값·시간·ID와 두 CSV의 SHA256을 DB에 보존합니다. CSV 전체를 메모리에서 처리하므로 대용량 입력의 처리 한도는 아직 검증하지 않았습니다.

3. 로컬 서비스 실행

OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 VECLIB_MAXIMUM_THREADS=1 \
python3 -m services.time_series_anomaly_diagnosis.application_server \
  --host 127.0.0.1 --port 8485 --public-host 127.0.0.1 \
  --source-database /path/new-analysis/univariate_ts.db \
  --history-database /path/new-analysis/analysis_history.sqlite3

브라우저에서 http://127.0.0.1:8485/를 열고 데이터셋 선택 → 분석 시작 → 분석 기록 → 결과 열기로 이동합니다. 각 ID를 선택하면 원본 측정값과 정규화한 정상 기준 비교 그래프를 볼 수 있습니다. 같은 DB·기록 경로로 재시작하면 결과를 다시 조회할 수 있습니다.

결과 해석과 현재 범위

  • 원시 CSV는 고정된 single_minirocket 정책으로 처리합니다. 과거 데이터셋과 이름이 같아도 과거 모델 선택이나 검토 근거를 가져오지 않습니다.
  • 점수는 1 − p이며 높을수록 정상 기준에서 드뭅니다. 이상일 확률이나 고장 원인의 확률은 아닙니다.
  • 목표 오탐 기준은 0.5%입니다. 기준 구간 199개 미만이면 p값 해상도가 부족해 자동 이상 판정을 차단합니다. 199개 이상이라는 사실만으로 실제 오탐률이 보장되지는 않습니다.
  • 분석 CSV의 정답을 알 수 없으므로 탐지율·오탐률·혼동행렬을 계산하지 않습니다. 결과가 없어도 성능이 좋다고 해석할 수 없습니다.
  • 현재는 로컬 CLI 가져오기와 기존 웹 결과 조회까지 지원합니다. 브라우저 파일 업로드·실시간 센서 수집·다변량 입력·자동 구간 분할·고장 원인 진단은 포함하지 않습니다.

검증 예제는 기능 확인용입니다. 실제 사용자 CSV에 대한 탐지 성능은 별도로 확인해야 합니다. 이번 작업은 새로운 모델의 성능 향상을 주장하지 않습니다.
