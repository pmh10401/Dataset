같은 MiniRocket 특징을 한 번 계산해 두 점수에 전달

공유 계산 API 구현을 완료했다. 회귀 검사 192개가 통과했고, 전체 1,119개 데이터셋 중 비교 가능한 1,117개의 TRAIN 표본에서 두 점수의 최대 오차가 0이었다. 고정 입력의 실행 시간은 약 38.0% 줄었다.

구현은 codex/shared-score-integration-antigravity 별도 작업 공간에 있다. 기존 서비스의 기본 호출과 경보 정책은 유지했다. 이 보고서는 계산 효율과 수치 동등성의 결과이며 탐지율·오탐률 개선을 주장하지 않는다.

공유하는 범위

계산처리
동일 입력·행 순서·전처리·참조 표본·시드의 full-FIT MiniRocket raw 특징LocalGap과 square_joint가 공유
square_joint의 centered-square 특징과 OAS필요한 것만 계산: raw·square 인코더 2개, OAS 1개
5개 OOF 모델, 다른 시드, 다른 FIT/CAL 분할서로 다른 학습 모델이므로 개별 계산
RMS 및 미선택 OAS 후보새 경로에서 계산하지 않음

공유는 함수 한 번의 실행 안에서 이루어진다. 별도의 영속 캐시나 캐시 키·무효화 시스템은 추가하지 않았다.

사용하지 않는 후보를 제거하고 특징을 공유한 합산 절감은 38.0%, square_joint만 계산하는 별도 경로와 비교한 순수 공유 절감은 4.5%다. 메모리 절감은 확인된 효과로 주장하지 않는다.

Apple M2 Max / 32 GiB, FIT 64행·query 32행·길이 256의 고정 난수 입력, 시드 20260721, 내부 스레드 1개. 경로별 별도 프로세스에서 첫 실행 후 3회 측정한 중앙값. RSS는 시작·워밍업을 포함한 프로세스 최대치다. 전체 서비스 및 모든 크기의 데이터셋에 같은 속도 비율이 적용된다는 뜻은 아니다. 이 난수 입력은 수치·시간 검사 용도이며 합성 이상 탐지 실험이 아니다.

검사 및 가속 선택

기존 3개 점수원과 두 시드, OOF 결과, 새 공유 경로의 golden 값, 128행 청크 경계, 입력 오류, 불변 출력, FIT가 다른 경우의 분리를 검사했다. 참조 수 999·1,000·1,001·3,500과 두 시드에서 표본 선택이 원본과 같았고, centered-square가 상수인 입력도 점수가 일치했다. 서비스 회귀 192개와 갱신 후 코드맵 검사 4개가 통과했다.

추가 Numba·PyTorch CPU 변환은 완전한 square_joint FIT·점수 단계에서 기존 NumPy보다 빨라지지 않았다. MLX·MPS의 명시적 float64 GPU 실행은 지원되지 않았다. 따라서 NumPy 변환 + 공식 aeon의 Numba MiniRocket + float64 NumPy/SciPy OAS를 사용한다. MLX 자동 dtype 변환을 float64 지원으로 간주하지 않았다.

Grok은 180초 내 응답이 없어 완료된 검토로 채택하지 않았다. AGY는 제공한 코드와 원본 수식만 검토해 차단 문제 없음으로 응답했다. Codex가 실제 원본 점수 비교와 회귀 검사를 확인했다.
