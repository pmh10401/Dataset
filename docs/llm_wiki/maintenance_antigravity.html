LLM Wiki의 세 층

Karpathy의 제안에서 원본·연결된 지식·유지 규칙의 구분을 가져왔다. 이 프로젝트는 기존 보고서·결과 파일을 원본으로 보존하고, 이 폴더의 연결된 HTML을 지식 층으로 사용한다. 이 페이지가 위키 유지 규칙이다. 프로젝트의 새 인간용 문서 HTML 규칙에 따라 Markdown 복제본·별도 검색 서버·벡터 DB를 추가하지 않았다. Karpathy LLM Wiki 원문

에이전트 읽기 순서: index → 질문과 관련된 주제 → 해당 원본. 수치와 결론은 원본에서 확인하고, 이 위키의 요약을 독립된 새 실험 근거로 재인용하지 않는다.

한 주장에 필요한 정보

  • 실험/시점, 정확한 방법과 대조군, 데이터셋·계열·평가 행 수 또는 해당 원본 링크.
  • 정상 TRAIN·합성 검증·이미 노출된 TEST·교차검증 목표 중 무엇을 썼는지.
  • 순위 평가인지 고정 문턱인지, 목표 FPR과 관측 FPR, 탐지 손실과 이득.
  • 관측 사실·판단·가설·미확인의 구분, 불확실성, 제외 사유, 후속 문서 관계.
  • 출처의 경로·SHA256과 확인 시점. 원본에 없는 원인이나 승인·완료 상태를 만들어 넣지 않는다.

수치 충돌 시 결과 artifact/독립 검산 → 실제 실행 기록 → 사전 프로토콜 → 인수인계·종합 보고서 순으로 확인한다. 프로토콜은 계획, 결과는 실제 수행 근거다. 후속 결과로 실패 이력을 지우거나 사전 계획을 소급 변경하지 않는다.

새 결과를 기록하는 절차

  1. 현재 사용자 요청 범위와 작업트리·Git 상태를 확인한다. 원본 DB·TEST 라벨·저장 가중치를 위키에 복제하거나 외부로 전송하지 않는다.
  2. 보고서와 aggregate 결과·검산 기록을 읽고 원본 해시를 확인한다. 기존 파일 해시가 달라지면 이유를 먼저 조사한다.
  3. sources_antigravity.json에 출처와 확인 범위를 등록한다. 기존 source ID는 유지하고 바뀐 원본의 이전 해시·정정 이유를 작업 기록에 남긴다. 승인 없는 원본 수정은 하지 않는다.
  4. 관련 주제·연표·현재 상태만 갱신한다. 새 결과가 이전 가설을 반박하면 양쪽 근거를 연결한다. ‘실패’와 ‘미실행’을 성공처럼 합치지 않는다.
  5. 문서 링크·fragment·출처 해시·핵심 수치·동일 집단 비교를 검사하고 verification_antigravity.json을 새 기록으로 갱신한다. 기존 검증의 원본은 원래 실험 폴더에 보존한다.
  6. 아래 로그에 날짜·입력·변경한 페이지·미검증 범위를 덧붙인다. 새 모델 실행·커밋·푸시는 문서 갱신과 별도 요청 범위다.

질의와 정기 점검

질문에 답할 때 해당 실험의 모집단·정책·TRAIN/TEST 경계를 함께 읽는다. 동일 수치처럼 보이더라도 family 평균·dataset 평균·전체 비율을 섞지 않는다. 새 비교 결론을 문서로 남길 때 원본을 함께 연결한다.

점검할 항목: 출처 없는 주장, 깨진 링크, 후속 결과가 있는데도 남은 ‘미실행’, 버전이 다른 ‘현재 최고’, 해시 불일치, source 등록 없이 바뀐 숫자, 읽을 수 없는 로컬 경로. LLM 제안은 검증된 결과로 자동 승격하지 않는다. 정기 실행이나 모니터링 자동화는 설치하지 않았다.

게시 파일 해시만 다시 확인하는 최소 명령이다. 체크아웃한 저장소의 위키 폴더에서 실행한다. 미게시 원본·성능 계산·DB는 검사하지 않는다.

python3 - <<'PY'
import hashlib, json
from pathlib import Path
m = json.loads(Path('sources_antigravity.json').read_text())
repo = Path.cwd().parents[1]
checked = 0
for source in m['sources']:
    published = source['publication']
    if published['status'] == 'local_only':
        continue
    path = repo / published['path']
    assert path.is_file(), source['id']
    assert hashlib.sha256(path.read_bytes()).hexdigest() == published['sha256'], source['id']
    checked += 1
print('게시 파일 해시 일치:', checked)
print('미게시 원본:', m['publication']['source_counts']['local_only'])
PY

저장소를 체크아웃하고 docs/llm_wiki/index_antigravity.html을 브라우저로 열면 문서를 읽을 수 있다. GitHub의 HTML 파일 화면은 소스를 표시하며, 이번 게시에 GitHub Pages 배포는 포함하지 않는다. 기존 저장소 출처 링크도 있으므로 위키 폴더만 떼어 복사하면 일부 근거가 빠진다. JSON의 roots는 원본 위치의 이력이며 게시 검사의 입력이 아니다. 미게시 자료의 검산은 원본 작업트리를 복구해야 가능하다.
