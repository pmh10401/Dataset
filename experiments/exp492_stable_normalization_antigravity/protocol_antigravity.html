Exp492: 정상 TRAIN 기반 정규화 안정화

Exp489–491 진단 후 개발 실험이다. 이미 분석한 개발 집단을 재사용하므로 독립 검증이나 자동 승격으로 해석하지 않는다. 기존 실험·원본 DB는 수정하지 않는다.

고정 변경

epsilon은 입력의 float64 변환 여부와 무관하게 float32 epsilon으로 고정한다. near-constant 조건은 모델링 규칙이며 모든 작은 변동이 반올림 오차라는 주장은 하지 않는다.

  • Hydra+MultiRocket의 공식 SparseScaler에서 sqrt-count 좌표의 TRAIN 평균 μ와 원래 결합 sigma를 사용한다. sigma ≤ 10·eps32·max(1, |μ|) 이고 sigma < 1인 열만 분모를 1로 변경한다. 원래 sqrt/clamp/zero mask를 유지한다.
  • 두 방법의 LocalGap RobustScaler(quantile_range=(10,90), 기본 centering/scaling, unit_variance=False)의 TRAIN q10/q90는 NumPy linear percentile로 계산한다. raw IQR ≤ 10·eps32·max(1,|q10|,|q90|) 이고 기존 유효 scale < 1인 열만 scale을 1로 변경한다.
  • 열 삭제·query clipping·log 변환·거리 공식 변경·LocalGap 반경 변경·하이퍼파라미터 탐색은 하지 않는다. 큰 분모를 줄이지 않는다. 비유한 입력·통계·출력은 오류로 처리한다.

쌍대 비교

Exp489/490과 동일한 125개 family 대표(각 family 중 n_train≥5인 dataset 사전순 첫 항목), PigAirwayPressure/PigArtPressure/PigCVP 제외. Hydra와 Hydra+MultiRocket 두 방법별 기존/안정화 분기를 비교한다. 원래 Exp449의 seed=20260721, 5 OOF folds, reference cap=1000, query chunk=128, reference seed salts, neighbors=3, 공식 aeon CPU 인코더와 파라미터를 유지한다. 각 방법당 원시 인코더 6회(5 OOF+full TRAIN)를 공유하되 정규화 이후 LocalGap은 분기별로 적합한다. MultiRocket StandardScaler 블록은 동일하게 공유한다.

매 fold와 full TRAIN에서만 통계·mask를 적합한다. 125개 모든 dataset, 두 방법, 두 분기의 score NPZ와 해시가 저장·검증된 후에만 TEST label 평가를 시작한다. 재개 시 코드·입력·버전·protocol binding과 점수 checksum을 검증한다. 누락·실패 family를 제외하고 성공으로 보고하지 않는다.

검증과 판정

합성 회귀에서 양의 상수·0 상수·작은 IQR·경계·큰 값·진짜 저분산·일반 열을 검사한다. 기존 분기는 별도 Exp449 호출과 atol=1e-8, rtol=1e-10 및 alpha=.005 후보 인덱스가 일치해야 한다. 반복 실행은 결정론적으로 같아야 한다. DiatomSizeReduction_normal_1와 ProximalPhalanxOutlineCorrect_normal_0의 정상 TRAIN smoke로 두 증폭 지점을 검증한다.

주 결과는 방법별 family 동등가중 평균 AUC, 평균/합계 ZF 및 승/패/동률이다. ZF는 기존 strict TEST-normal-max 초과 이상 샘플 수이며 배포 임계값 선정이 아니다. 수치 결과는 유한 개수, feature/score 최대 절댓값, 원래 spread/scale·tolerance·mask·실제 변경 열 수, OOF (q95−q50)/IQR 및 (q99−q50)/IQR로 기록한다. IQR=0 비율은 undefined(null)로 둔다. 안정화와 성능 개선을 별도로 판단한다. 라우팅·Ridge 성능 개선은 이 실험만으로 주장하지 않는다.

실행

논리 CPU−1 workers, 내부 thread=1. PyTorch/MLX/MPS/Numba를 평가하되 공식 aeon·sklearn을 재작성하지 않는다. 분모 마스킹은 비중이 작은 벡터 연산이며 비교 가능성과 단순성을 우선한다. GPU로 승격하려면 전체 단계 전송·동기화 포함 parity와 ≥1.1배 속도가 필요하다. 사용 backend·버전·smoke·fallback 사유는 manifest에 기록한다.

python -m experiments.exp492_stable_normalization_antigravity.run_antigravity --mode smoke
